# 계획 3 — 옷장

> 상태: **1~5단계 모두 완료** (2026-09-26) — 계획 3 구현 끝
> 계획 1·2와 **독립적**이라 순서와 상관없이 따로 구현할 수 있다.
> 작업은 "작업 순서"의 단계별로 진행하고, 각 단계마다 앱을 실행해 확인한 뒤 다음 단계로 넘어간다.

---

## 1. 목표

1. **옷 종류 자동 분류**: 패션 전용 AI 모델로 셔츠·바지·치마 등을 자동 분류한다.
2. **누끼(배경 제거)**: 옷 사진의 배경을 자동으로 지워 옷장 화면을 정돈한다.
3. **착용 기록**: "오늘 이 코디 입었어요"를 날짜별로 기록한다.
4. **안 입는 옷 알림**: 3개월(90일) 넘게 안 입은 옷을 알려준다.

---

## 2. 확정된 결정 사항

| 항목 | 결정 |
|---|---|
| 분류 AI | **B안: DeepFashion2로 학습된 YOLO 모델** (서버에서 실행) |
| 누끼 AI | **ML Kit 피사체 분리 (Subject Segmentation)** — 폰 안에서 동작 |
| 안 입는 옷 알림 | **앱 안에서만 표시** (푸시 알림 X) |
| 계절 제외 규칙 | **넣는다** — 지금 계절에 안 맞는 옷은 알림에서 제외 |
| 기준 기간 | 90일 (3개월) |
| 서버 꺼졌을 때 | 사용자가 직접 종류 선택 (지금 방식 유지) |
| 시연 | 과거 날짜 착용 기록을 넣는 **"시연용 샘플 데이터" 버튼** |

## 3. 현재 코드 상태 (문제점)

| 문제 | 위치 | 영향 |
|---|---|---|
| 지금 AI(YOLOv8 COCO)는 셔츠·바지·치마 개념이 없음 | `backend/detection.py` | 가방류가 아니면 모두 "상의"로 처리됨 (`AddClothingViewModel.kt`) |
| 샘플 옷 12벌이 코드에 고정 | `WardrobeScreen.kt`의 `allClothes` | 저장소에 없어서 착용 기록 불가 |

| 대표 색을 사진 전체에서 추출 | `AddClothingViewModel.dominantColor` | 배경색이 옷 색으로 잘못 잡힐 수 있음 |

## 4. 기능 1 — 옷 종류 분류 (DeepFashion2 YOLO)

### 4-1. 모델이 구분하는 13종류 → 앱 분류로 변환

| DeepFashion2 종류 | 앱 대분류 | 앱 자동 소분류 |
|---|---|---|
| short sleeve top | 상의 | 반팔 상의 |
| long sleeve top | 상의 | 긴팔 상의 |
| vest / sling | 상의 | 민소매 |
| short sleeve outwear | 아우터 | 반팔 아우터 |
| long sleeve outwear | 아우터 | 긴팔 아우터 |
| shorts | 하의 | 반바지 |
| trousers | 하의 | 긴바지 |
| skirt | 하의 | 치마 |
| short/long sleeve dress, vest dress, sling dress | 원피스 | 반팔/긴팔/민소매 원피스 |

### 4-2. 세부 종류는 "AI 추천 + 사용자 선택"
- DeepFashion2는 **셔츠·니트·맨투맨처럼 소재/디자인 차이는 구분하지 못한다.**
- 그래서 AI가 "긴팔 상의"라고 판단하면, 그 안의 세부 종류 칩(셔츠 / 블라우스 / 니트 / 맨투맨 / 후드티 / 긴팔티)을 보여주고 **사용자가 한 번 탭**해서 고른다. (선택 안 하면 "긴팔 상의"로 저장)

| 자동 소분류 | 세부 종류 선택지 |
|---|---|
| 반팔 상의 | 반팔티, 셔츠, 블라우스, 폴로 |
| 긴팔 상의 | 긴팔티, 셔츠, 블라우스, 니트, 맨투맨, 후드티 |
| 긴팔 아우터 | 자켓, 코트, 패딩, 가디건, 점퍼 |
| 긴바지 | 청바지, 슬랙스, 면바지, 트레이닝팬츠 |
| 치마 | 미니스커트, 롱스커트 |

### 4-3. 모델이 모르는 것
- **신발·가방·액세서리는 DeepFashion2에 없다.**
- 가방류(핸드백·백팩 등)는 **기존 COCO YOLO를 함께 돌려** 잡고, 신발·기타는 **사용자 선택**.
- 서버에서 두 모델을 모두 실행하고 결과를 합친다.

### 4-4. 계절감 (규칙으로 자동 지정, 수정 가능)

| 조건 | 계절 |
|---|---|
| 반팔·민소매·반바지·민소매/반팔 원피스 | 여름 |
| 패딩, 코트 | 겨울 |
| 자켓, 가디건, 점퍼, 맨투맨, 후드티 | 봄·가을 |
| 그 외 (긴팔티, 셔츠, 청바지, 슬랙스 등) | 사계절 |

### 4-5. 모델 파일 준비
- 먼저 **공개된 DeepFashion2 학습 YOLOv8 가중치**를 찾아 사용 (라이선스 확인 필요, DeepFashion2 데이터는 비상업 연구용)
- 적당한 공개 가중치가 없으면 Colab(GPU)에서 DeepFashion2로 직접 추가 학습
- 파일 위치: `backend/models/deepfashion2_yolov8.pt`, 받는 방법은 `backend/README.md`에 기록
- ~~`ultralytics`는 이미 설치되어 있음~~ → 실제로는 미설치였음. `pip install --no-deps ultralytics ...`로 설치 (backend/README.md 참고)
- 사용 모델: 허깅페이스 Bingsu/adetailer의 `deepfashion2_yolov8s-seg.pt` (윤곽 마스크 포함 → "옷만 오려내기"에 활용)

### 4-6. 여러 벌이 잡힐 때
- 착용 사진처럼 상의·하의가 함께 잡히면 **가장 크게 잡힌 옷을 기본 선택**하고, 다른 후보를 칩으로 보여줘 바꿀 수 있게 한다.

## 5. 기능 2 — 누끼 (배경 제거)

### 5-1. 처리 순서

```
옷 사진 → ① 누끼 (ML Kit 피사체 분리) → ② 종류 분류 (서버) → ③ 대표 색 추출 → 옷장 저장
```

- 누끼를 먼저 해서 **분류와 색 추출이 옷만 보고** 판단하게 한다.
- 서버로 보낼 때는 투명 배경을 **흰색으로 채워서** 보낸다. (모델이 투명 배경을 학습하지 않았기 때문)
- 기존 `selfie_segmenter`는 사람 전용이라 옷에는 사용하지 않는다.

### 5-2. 저장과 표시
- 배경이 투명한 **PNG로 앱 전용 폴더에 저장** (갤러리 권한 문제도 해결)
- 옷장 칸: **같은 크기 · 같은 배경색 · 가운데 정렬**
- 누끼 결과가 이상하면 **"원본으로 저장"** 선택 가능
- 촬영 팁: "옷을 바닥·침대에 펼치거나 옷걸이에 걸어서, 옷과 색이 다른 배경에서 찍어주세요"

## 6. 기능 3 — 착용 기록

```
옷장 화면 → [오늘 입은 옷 기록] → 옷 여러 벌 선택 (상의 + 하의 + 신발 …)
          → 날짜 (기본 오늘, 변경 가능) → 저장
```

- 기록 1건 = **날짜 + 입은 옷 ID 목록 + (선택) 한 줄 메모**
- **달력 화면**: 날짜를 누르면 그날 입은 코디 표시
- 옷 상세: **착용 횟수 · 마지막 착용일**
- 통계: **가장 많이 입은 옷 TOP 5**
- 저장: SharedPreferences + JSON (새 라이브러리 없음)

## 7. 기능 4 — 안 입는 옷 알림 (앱 안 표시)

### 7-1. 규칙
- 기준일 = **마지막 착용일** (한 번도 안 입었으면 **옷장 등록일**)
- 오늘 − 기준일 ≥ **90일** → 안 입은 옷
- **제외**:
  - 지금 계절에 안 맞는 옷 (예: 여름에 패딩·코트, 겨울에 반팔·반바지). 사계절 옷은 항상 검사
  - 사용자가 **[계속 보관]**을 누른 옷

### 7-2. 계절 판단 (월 기준)

| 월 | 현재 계절 |
|---|---|
| 3~5월 | 봄 |
| 6~8월 | 여름 |
| 9~11월 | 가을 |
| 12~2월 | 겨울 |

- "봄·가을" 옷은 봄·가을에 검사

### 7-3. 화면
- 옷장 화면 위쪽 알림 카드: **"3개월 넘게 안 입은 옷이 5벌 있어요"**
- 누르면 목록 + 옷마다 "마지막 착용 4개월 전"
- 옷마다 버튼: **[정리하기(삭제)]** / **[계속 보관]** — ([이번 주에 입어보기]는 구현하지 않기로 결정)
- [계속 보관] = **A안**: 누른 날부터 90일을 다시 센다 (기준일 = 마지막 착용일·등록일·보관일 중 가장 최근)

### 7-4. 시연용 샘플 데이터
- 버튼 하나로 **과거 날짜 착용 기록**을 넣어, 3개월을 기다리지 않고 알림을 시연
- 개발 중에만 보이도록 숨김 처리 가능

## 9. 작업 순서 (5단계)

| 단계 | 내용 | 확인 방법 |
|---|---|---|
| 1 | **옷장 데이터 정리**: ID, 저장소 통일, 샘플 옷 이동, 즐겨찾기 저장 | 앱을 껐다 켜도 옷·하트가 유지되는지 |
| 2 | **누끼** + 앱 폴더 저장 + 누끼 기준 색 추출 | 여러 옷 사진으로 배경 제거·색 확인 |
| 3 | **DeepFashion2 분류** (서버) + 세부 종류 선택 + 계절 규칙 | 셔츠·바지·치마·원피스·아우터 분류 확인 |
| 4 | **착용 기록** + 달력 + 통계 | 며칠 기록 후 달력·횟수 확인 |
| 5 | **안 입는 옷 알림** + 계절 제외 + 시연용 샘플 데이터 | 샘플 데이터로 알림 카드 확인 |

## 10. 알려진 한계

- DeepFashion2는 **셔츠·니트 등 세부 종류를 구분 못 함** → 사용자 선택으로 보완
- DeepFashion2는 주로 사람이 입은 사진·쇼핑몰 사진으로 학습 → **바닥에 펼친 옷 사진**은 정확도가 낮을 수 있음 (3단계에서 테스트)
- 신발·액세서리는 자동 분류 불가 (가방류만 COCO로 보완)
- 자동 분류는 **서버가 켜져 있어야** 동작 → 발표 때 PC 서버 실행 필요
- DeepFashion2 데이터는 비상업 연구용 → 캡스톤 시연 용도로만 사용
- 계절 규칙은 대략적인 기준이므로 사용자가 수정 가능
