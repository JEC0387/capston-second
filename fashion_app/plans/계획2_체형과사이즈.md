## 1. 목표

1. **사이즈 추천**: 계획 1에서 잰 cm 치수를 쇼핑몰 사이즈표와 비교해 "이 셔츠는 L 사이즈가 맞아요"라고 알려준다.
2. **측정 기록 그래프 확장**: 계획 1의 날짜별 기록을 더 다양한 그래프로 보여준다.

모든 계산은 폰 안에서 처리하며 서버(`backend/`)는 수정하지 않는다.

## 2. 확정된 결정 사항

| 항목 | 결정 |
|---|---|
| 둘레가 없을 때 (옆모습 건너뜀) | **C안: 폭으로 둘레를 대략 추정("정확도 낮음" 표시) + 줄자 값 직접 입력 가능 (입력값 우선)** |
| 사용자 선호 핏 설정 | **넣지 않는다** — 여유분은 상품 데이터에 적힌 핏(정핏/오버핏 등)으로 결정 |

| 사이즈표 데이터 | 쇼핑 화면 옷 상품의 사이즈표를 **직접 옮겨 적은 JSON** (자동 수집 X) |
| 얼굴 사진 | **저장하지 않음**, 결과만 저장 |

## 3. 기능 1 — 사이즈 추천

### 3-1. 사이즈표 두 종류

| 종류 | 예시 | 비교 방법 |
|---|---|---|
| 신체 기준표 | "가슴둘레 95~100cm → L" | 몸 치수와 바로 비교 |
| 실측 사이즈표 (무신사 대부분) | "L: 어깨 48, 가슴단면 58, 총장 72" | 옷을 잰 값이므로 **몸 치수 + 여유분**과 비교 |

### 3-2. 여유분 (상품의 핏으로 결정)

- 사이즈표 JSON에 상품마다 **핏 종류**(정핏 / 레귤러 / 오버핏)를 적어둔다.
- 오버핏 상품은 원래 크게 나오므로 여유분 기준도 크게 잡아야, 오버핏 옷에 한 치수 작은 사이즈를 추천하는 실수를 막을 수 있다.
- 여유분 기준값은 `SizeRecommender.kt` 한 곳에 모아서 조정 가능하게 한다.

```
내 가슴둘레 88cm + 여유분 10cm(레귤러) = 98cm 필요
옷 가슴단면 × 2 = 옷 가슴둘레
   M: 50×2 = 100cm ✅ 딱 맞음
   L: 55×2 = 110cm   넉넉함
```

### 3-3. 비교 항목

| 옷 종류 | 비교 항목 (옷 ↔ 내 몸) |
|---|---|
| 상의 | 어깨너비 ↔ 어깨너비 / 가슴단면×2 ↔ 가슴둘레+여유 / 소매길이 ↔ 팔 길이 |
| 하의 | 허리단면×2 ↔ 허리둘레+여유 / 엉덩이단면×2 ↔ 엉덩이둘레+여유 / 총장 ↔ 다리 길이 |

- 신발은 발 길이가 필요하므로 **제외**

### 3-4. 둘레가 없을 때 (C안)
1. 기본: 정면 폭으로 둘레를 **대략 추정**하고 "정확도 낮음 · 옆모습을 찍으면 더 정확해요" 표시
2. 선택: 사용자가 **줄자로 잰 둘레를 직접 입력**하면 그 값을 **최우선** 사용
3. 우선순위: **직접 입력 > 옆모습으로 추정 > 폭으로 대략 추정**

### 3-5. 결과 표시

```
👕 추천 사이즈: L
 ✔ 어깨  딱 맞아요 (내 어깨 42 · 옷 44)
 ✔ 가슴  적당히 여유 있어요
 ⚠ 소매  1~2cm 길 수 있어요
 ─ M은 어깨가 2cm 작아요 / XL은 가슴이 12cm 넉넉해요
```

- 추천 사이즈가 상세 화면의 **사이즈 버튼에 자동 선택**
- 쇼핑 목록에 사이즈표가 있는 상품은 **"내 사이즈 L"** 배지
- 치수가 없으면 "체형 분석하고 내 사이즈 알아보기" 버튼

### 3-6. 사전 작업 (현재 코드 문제)
- `ProductDetailScreen.kt`는 상품 하나(저스트메리드 니트)로 고정 → **누른 상품의 번호를 넘겨받아 표시**하도록 변경
- `ShopScreen.kt` 안의 상품 목록(8개)을 **공용 파일(`data/ProductData.kt`)로 이동**해 상세 화면에서도 사용

## 5. 기능 3 — 퍼스널 컬러 진단

### 5-1. 동작 원리

```
얼굴 사진 → ML Kit 얼굴 인식 → 양쪽 볼 위치 → 볼 영역 색 평균
         → RGB → Lab 변환 → 4계절 판정 → 색 추천
```

| 판단 | 기준 | 결과 |
|---|---|---|
| 웜 vs 쿨 | 피부가 노란 기 쪽인지 붉은(핑크) 기 쪽인지 (Lab 색상각) | 웜톤 / 쿨톤 |
| 밝기 | 피부 명도 (Lab L*) | 봄·여름 (밝음) vs 가을·겨울 (깊음) |
| 선명도 | 채도 (Lab 채도) | 판정 보조 + 설명 |

- 판정 기준값은 `SkinToneClassifier.kt`에 모아서 조정 가능하게

### 5-2. 촬영 가이드 (계획 1 부품 재사용)
- 계획 1의 **음성 안내 / 체크리스트 / 자동 촬영** 재사용, 가이드 모양만 **얼굴 타원**
- **앞 카메라** (셀카)

**촬영 전 체크리스트**
- ☀️ 낮에 창가 자연광 (노란 전등·형광등 피하기)
- 🙅 화장 지우기, 앞머리 넘기기
- 🪟 창문을 등지지 않기 (역광 X)

**실시간 자동 검사**

| 검사 | 방법 | 안내 문구 |
|---|---|---|
| 얼굴 위치·크기 | 얼굴 인식 박스 | "얼굴을 타원 안에 맞춰주세요" |
| 정면 | 얼굴 좌우 회전 각도 | "정면을 봐주세요" |
| 밝기 | 얼굴 평균 밝기 | "너무 어두워요, 창가로 가주세요" |
| 한쪽 그늘 | 좌우 볼 밝기 차이 | "빛이 한쪽에서만 들어와요, 창문을 마주 봐주세요" |

### 5-3. 조명 영향 줄이기
- 흰 종이 보정은 넣지 않고, **촬영 전 체크리스트 + 실시간 밝기·그늘 검사**로 조명 영향을 줄인다.
- 결과 화면에 "낮에 창가 자연광에서 찍었을 때 가장 정확해요" 안내

### 5-4. 결과 & 연결
- 계절 유형 + 설명 + **추천 색 팔레트 12색** + 피할 색 + 립·헤어 팁
- **쇼핑 연결**: 상품 대표 색이 내 팔레트와 가까우면 **"내 톤에 어울려요 🎨"** 배지
- 결과 저장 → 마이페이지 표시
- 안내: "카메라 진단은 참고용이며 전문 진단(드레이핑)과 다를 수 있어요"
- 얼굴 사진은 폰 안에서만 분석하고 **저장하지 않음**

## 7. 작업 순서 (5단계)

| 단계 | 내용 | 필요한 선행 작업 | 확인 방법 |
|---|---|---|---|
| 1 | 상품 목록 공용화 + 상세 화면이 누른 상품을 표시 | 없음 | 상품마다 다른 상세 화면이 뜨는지 |
| 2 | 사이즈표 데이터 + 사이즈 추천 + 둘레 직접 입력 | 계획 1 **2단계** | 실제 입는 사이즈와 추천이 맞는지 |
| 3 | 기록 그래프 확장 | 계획 1 **4단계** | 여러 번 측정 후 그래프·타임라인 확인 |
| 4 | 퍼스널 컬러 촬영 가이드 + 분석 | 계획 1 **1단계** 부품 | 자연광/전등 아래 결과 비교 |
| 5 | 색 추천 + 쇼핑 연결 | 2-4단계 | 쇼핑 화면 배지 확인 |

## 8. 알려진 한계

- 폭으로 추정한 둘레는 오차가 커서 사이즈 추천도 부정확할 수 있음 → "정확도 낮음" 표시, 직접 입력 권장
- 사이즈표는 시연용으로 일부 상품만 수동 입력
- 여유분·퍼스널 컬러 판정 기준값은 초기값이며 실제 테스트로 조정 필요
- 퍼스널 컬러는 조명 영향이 커서, 노란 전등 등 자연광이 아닌 곳에서 찍으면 웜톤 쪽으로 치우칠 수 있음
- 카메라 퍼스널 컬러 진단은 전문 드레이핑 진단을 대신할 수 없음 (참고용)
