# 계획 4 — 추천

> 상태: **1·2·3단계 구현 완료** (2026-10-03) — 1: 코디 엔진·색 규칙·오늘 날씨 → 홈, 스타일 태그·신발 세부 종류, 옷 부족 안내. 2: 상황별 코디(SituationRules) + 코디 화면(OutfitRecommendScreen), 옛 고정 코디 삭제. 3: 5일 예보(낮 9~18시 평균 기온으로 코디, 비 60% 이상이면 비 오는 날), 홈 "내일 코디"·🔔 알림, [5일 예보] 탭, 여행 날짜 선택, 일교차 10도 이상이면 겉옷 포함, 위치 5초 넘으면 기본 좌표, API 키 local.properties 이동. (퍼스널 컬러는 계획 2가 아직 없어 미반영)
> **계획 3(옷장)이 먼저 구현되어 있어야 한다.** (옷 ID, 세부 종류, 계절, 누끼 기준 색, 착용 기록 사용)
> 계획 2의 퍼스널 컬러가 있으면 색 점수에 추가로 반영한다. (없어도 동작)
> 작업은 "작업 순서"의 단계별로 진행하고, 각 단계마다 앱을 실행해 확인한 뒤 다음 단계로 넘어간다.

## 1. 목표

1. **옷장 코디 조합**: 옷장의 옷으로 상의+하의+신발(+아우터) 코디를 색 규칙과 오늘 날씨에 맞춰 만든다.
2. **"이것만 사면 코디 완성"**: 옷장을 분석해 "베이지 슬랙스 하나만 사면 코디 5개가 더 생겨요"라고 알려준다.
3. **내일·5일 예보 코디**: 날씨 예보로 "내일 기온이 낮아요, 가디건 챙기세요"처럼 미리 추천한다.
4. **상황별 코디**: 면접·데이트·여행·운동 상황에 맞는 코디를 추천한다.
5. **취향 학습 확장**: 스타일뿐 아니라 좋아요 누른 코디의 **색·종류**까지 학습한다.

## 2. 확정된 결정 사항

| 항목 | 결정 |
|---|---|
| 추천 방식 | AI 학습 없는 **규칙 + 점수** 방식의 코디 조합 엔진 1개를 모든 기능이 공유 |
| 핏(슬림/레귤러/오버) | **넣지 않는다** — 옷 등록 칩 없음, 핏 학습 없음 |

## 4. 핵심 부품 — 코디 조합 엔진

```
옷장 옷들 ─▶ ① 걸러내기 ─▶ ② 조합 만들기 ─▶ ③ 점수 매기기 ─▶ ④ 좋은 코디 N개 + 이유
            (날씨·계절·상황)  (상의+하의+신발       (색 조합 + 날씨 + 상황
                             +필요시 아우터,        + 내 취향 + 착용 기록
                             원피스면 하의 없음)     + 퍼스널 컬러(있으면))
```

- 모든 조합을 계산해도 폰에서 충분히 빠름 (예: 20×15×5 = 1,500개)
- **다양성**: 같은 상의·하의가 반복되지 않도록 골고루 선택
- **이유 표시**: "네이비 + 베이지는 차분한 조합이에요 · 오늘 14도라 자켓을 더했어요"
- **착용 기록 연결 (계획 3)**
  - 최근(어제·그저께) 입은 옷 → 감점
  - 오래 안 입은 옷 → 가산점 (계획 3 알림의 [이번 주에 입어보기]와 연결)
- **옷이 부족할 때**: 고정 코디로 대체하지 않고 안내
  - 최소 조건: (상의 1벌 + 하의 1벌) 또는 원피스 1벌, 그리고 신발 1켤레
  - 예: "코디를 만들려면 하의가 1벌 이상 필요해요" + [옷 등록하기] 버튼
  - 시연은 계획 3의 샘플 옷 12벌로 충분

## 5. 기능 1 — 옷장 코디 (색 규칙 + 오늘 날씨)

### 5-1. 색 조합 규칙
옷 색을 색상 / 밝기 / 선명도로 나눠 판단한다.

| 규칙 | 설명 | 점수 |
|---|---|---|
| 무채색·뉴트럴 | 블랙, 화이트, 그레이, 베이지, 네이비, 데님은 어디든 어울림 | ➕ |
| 톤온톤 | 같은 색 계열, 밝기만 다르게 (베이지 + 브라운) | ➕ |
| 포인트 컬러 1개 | 뉴트럴 + 선명한 색 하나 | ➕ |
| 명도 대비 | 상의·하의 밝기가 적당히 다름 | ➕ |
| 3색 이내 | 뉴트럴 제외 색이 너무 많으면 복잡 | ➖ |
| 원색 충돌 | 선명한 원색 2개 이상 (빨강 + 초록) | ➖ |
| 퍼스널 컬러 (계획 2) | 내 톤 팔레트에 가까운 색 | ➕ |

- 기준값은 `ColorHarmony.kt`에 모아서 조정 가능하게

### 5-2. 날씨 규칙

| 날씨 | 규칙 |
|---|---|
| 23도 이상 | 반팔·반바지 가능, 아우터 없음 |
| 20~22도 | 긴팔 또는 얇은 아우터(가디건) |
| 12~19도 | 아우터 필요 (자켓·가디건·점퍼) |
| 5~11도 | 코트·니트 우선 |
| 5도 미만 | 패딩·코트 우선 |
| 비·눈 | 밝은 하의·흰 신발 감점, 샌들 제외 |
| 계절 | 계획 3 계절 태그가 지금 계절과 안 맞으면 제외 |

- 온도 구간은 기존 `advice()` 규칙과 맞춘다.

### 5-3. 스타일 자동 태그
옷 종류·색으로 스타일을 자동으로 붙이고, 사용자가 수정할 수 있다.

| 옷 | 스타일 |
|---|---|
| 셔츠, 슬랙스, 로퍼, 구두, 코트 | 클래식 |
| 무채색·뉴트럴 단색 니트·티·슬랙스 | 미니멀 |
| 맨투맨, 청바지, 스니커즈, 반팔티 | 캐주얼 |
| 후드티, 카고팬츠, 점퍼 | 스트릿 |
| 가디건, 코듀로이, 체크 등 | 빈티지 |

- 코디의 스타일 = 들어간 옷 스타일의 다수결

### 5-4. 화면
- 홈 "오늘의 AI 코디" → **옷장 옷(누끼 사진)으로 만든 코디** 3~4개
- 코디 카드마다 이유 + 👍 👎 버튼

## 6. 기능 2 — "이것만 사면 코디 완성"

### 6-1. 원리: 가상으로 하나씩 넣어보기

```
후보: 베이지 슬랙스
  지금 옷장으로 만들 수 있는 좋은 코디(기준 점수 이상): 12개
  베이지 슬랙스를 가상으로 넣으면: 17개
  → "베이지 슬랙스 하나만 사면 코디 5개가 더 생겨요!"
```

- 후보: **기본템 약 30개** (흰 셔츠, 베이지 슬랙스, 청바지, 네이비 가디건, 흰 스니커즈, 검정 로퍼 등) + **쇼핑 화면 상품**
- 늘어나는 코디 수가 많은 순서로 **TOP 3**
- 누르면 새로 생기는 코디 예시 + [쇼핑에서 찾기]

### 6-2. 덤 기능
- **외톨이 옷**: 어떤 조합에도 안 들어가는 옷 → "이 체크 셔츠는 어울리는 하의가 없어요"
- **상황별 부족 아이템**: "면접 코디를 만들려면 흰 셔츠가 필요해요"

## 7. 기능 3 — 내일·5일 예보 코디

### 7-1. 예보 데이터
- OpenWeatherMap 무료 **`/data/2.5/forecast`**: 5일, 3시간 간격 (40개)
- **날짜별로 묶어서** 최저·최고 기온, 비 올 확률, 대표 날씨 계산
- 5일보다 긴 예보는 유료/카드 등록 필요 → 범위 밖

### 7-2. 미리 알림 문구

| 조건 | 문구 예 |
|---|---|
| 내일이 오늘보다 5도 이상 추움 | "내일은 오늘보다 6도 낮아요, 가디건 챙기세요" |
| 기온이 크게 오름 | "내일은 더워져요, 반팔 코디를 준비했어요" |
| 일교차 10도 이상 | "아침저녁으로 쌀쌀해요, 겉옷을 챙기세요" |
| 비 올 확률 60% 이상 | "내일 비 소식이 있어요, 우산 챙기고 밝은 하의는 피하세요" |

### 7-3. 화면
- 홈에 **"내일 코디" 카드** (문구 + 옷장 코디)
- 코디 화면에 **5일 날씨 띠** → 날짜 누르면 그날 코디
- 알림은 **앱 안에서만**

### 7-4. API 키 정리
- `WeatherRepository.kt`에 적힌 API 키를 `local.properties`로 옮기고 `build.gradle.kts`에서 읽어오게 변경 (코드 공유 시 키 노출 방지)
- **팀원 설정 방법**: `fashion_app/local.properties`(Git에 안 올라감)에 한 줄 추가 → `OWM_API_KEY=발급받은키`
  - 키가 없으면 앱은 동작하지만 예보와 (서버 미연결 시) 현재 날씨를 불러오지 못한다

## 8. 기능 4 — 상황별 코디 (4개)

| 상황 | 우선하는 옷 | 빼는 옷 | 색 규칙 |
|---|---|---|---|
| 면접 | 셔츠, 블라우스, 슬랙스, 자켓, 로퍼·구두 | 후드티, 반바지, 운동화, 트레이닝 | 무채색·네이비 위주, 포인트 컬러 X |
| 데이트 | 내 취향 스타일 가중치 ↑, 원피스·니트·셔츠 | 트레이닝 | 밝은 포인트 1개 허용 |
| 여행 | 청바지, 면바지, 편한 상의, 운동화·스니커즈 | 구두, 힐 | 자유 (레이어드 가산점) |
| 운동 | 반팔티, 트레이닝팬츠, 반바지, 운동화 | 그 외 전부 | 자유 |

- **여행**: 날짜를 고르면(5일 이내) 그날 예보 반영
- 맞는 옷이 없으면 기능 2와 연결: "운동 코디를 만들려면 트레이닝팬츠가 필요해요"
- 규칙표는 `SituationRules.kt` 한 곳에서 관리 (나중에 상황 추가 쉬움)
- 필요한 신발 세부 종류: 운동화, 스니커즈, 로퍼, 구두, 샌들, 부츠, 힐 (계획 3 옷 등록 화면에 추가)

## 9. 기능 5 — 취향 학습 확장 (스타일 + 색 + 종류)

### 9-1. 학습 항목

| 항목 | 예시 | 지금 |
|---|---|---|
| 스타일 | 미니멀, 캐주얼, 클래식, 스트릿, 빈티지 | ✅ 있음 |
| 색 | 베이지 계열, 네이비 계열 … + 조합 방식(톤온톤, 포인트 컬러) | 🆕 |
| 종류 | 슬랙스, 니트, 셔츠 … | 🆕 |

- 점수: **좋아요 +2 / 싫어요 −1** (기존과 동일), 코디에 포함된 모든 속성에 반영
- **"오늘 이 코디 입었어요" (계획 3)** = 약한 좋아요 **+1**

### 9-2. 좋아요를 누르는 곳
1. 추천된 **옷장 코디 카드**의 👍 👎
2. 기존 **취향 카드 10장** (색·종류 정보를 붙여 함께 학습)

### 9-3. 활용
- 코디 엔진의 **"내 취향" 점수**에 반영
- 마이페이지 **취향 리포트**: "베이지·네이비를 좋아해요 · 슬랙스를 자주 골라요 · 미니멀 스타일"
- 좋아요가 적을 때는 규칙 점수 위주로 추천

## 11. 작업 순서 (5단계)

| 단계 | 내용 | 먼저 필요한 것 | 확인 방법 |
|---|---|---|---|
| 1 | 스타일 태그·신발 종류 보강 + **코디 엔진 + 색 규칙 + 오늘 날씨** → 홈 연결, 옷 부족 안내 | 계획 3의 1·3단계 | 샘플 옷장으로 코디·이유가 자연스러운지 |
| 2 | **상황별 코디** (4개) | 1단계 | 상황마다 맞는 옷만 나오는지 |
| 3 | **5일 예보** + 내일 코디 카드 + API 키 이동 | 1단계 | 예보 문구·날짜별 코디 확인 |
| 4 | **취향 학습 확장** + 취향 리포트 + 엔진 반영 | 1단계 | 좋아요 후 추천이 취향 쪽으로 바뀌는지 |
| 5 | **"이것만 사면"** + 외톨이 옷 + 상황별 부족 아이템 | 1·2단계 | 옷장을 바꿔가며 추천 아이템 확인 |

## 12. 알려진 한계

- 색 규칙·점수 기준값은 초기값이며, 실제로 코디를 보면서 조정 필요
- 옷의 대표 색 1개만 사용 → 줄무늬·체크 등 패턴은 반영 못 함
- 무료 예보는 최대 5일
- 옷장에 옷이 적으면 추천이 나오지 않음 (고정 코디 대체 없음)
- 핏은 고려하지 않음
- 스타일 자동 태그는 대략적인 규칙이라 사용자 수정 필요할 수 있음
