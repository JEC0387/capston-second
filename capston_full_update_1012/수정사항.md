
## 실행 방법

### 0. 실행 전 준비물

**서버 (PC)**

| 항목 | 요구사항 |
|---|---|
| 파이썬 | **3.10 ~ 3.12 권장** (3.10.11에서 동작 확인) |
| 인터넷 | 처음 설치 · 처음 실행 때 필요 (라이브러리 · AI 모델 내려받기) |
| 디스크 | 여유 **3~5GB** (PyTorch가 큼) |
| GPU | 필요 없음 (CPU로 동작하도록 설정됨) |

- `pip install -r requirements.txt` 때 **PyTorch**가 함께 설치되어 시간이 꽤 걸립니다.
- AI 모델 2개는 저장소에 없고, 서버가 처음 요청을 받을 때 자동으로 내려받습니다.
  `yolov8n.pt`(약 6MB, 객체 탐지) · DeepFashion2 모델(약 24MB, 옷 분류)
- (선택) 서버의 현재 날씨는 환경변수 `OWM_API_KEY`가 있어야 실제 날씨를 보여 줍니다. 없으면 "맑음 22도"로 대신합니다.
  (설정 방법은 `backend/README.md`)

**앱**

| 항목 | 요구사항 |
|---|---|
| Android Studio | **최신 버전** 권장 (AGP 9.1 · Gradle 9.3 사용 — 오래된 버전은 "지원하지 않는 버전" 오류) |
| Java(JDK) | 따로 설치 필요 없음 (Android Studio에 포함) |
| Android SDK | **SDK Platform 37** (Android Studio가 설치하라고 안내하면 설치) |
| 인터넷 | 처음 열 때 Gradle · 라이브러리 자동 다운로드 |
| 폰 · 에뮬레이터 | **안드로이드 7.0(API 24) 이상**. 배경 제거 · 가상 피팅 몸 위치 찾기(ML Kit)는 **구글 플레이 서비스** 필요 → 에뮬레이터는 "Google Play"가 붙은 시스템 이미지로 만들기 |

- 새 컴퓨터에서는 `fashion_app/local.properties`에 **날씨 API 키**를 직접 넣어야 합니다 (아래 "2. 앱" 참고).
  SDK 위치(`sdk.dir`)는 Android Studio가 자동으로 채웁니다.

### 1. 서버 (PC)

처음 한 번: `backend/.env.example` 을 복사해 `backend/.env` 로 저장하고, `DATABASE_URL=` 뒤에 **Supabase 주소**를 넣습니다.
(주소 · 비밀번호는 팀장에게 개인톡으로 받기. 자세한 방법은 `backend/README.md` → "Supabase DB 준비")

```bash
cd backend
pip install -r requirements.txt
python -m uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

- 옷 종류를 분류하는 **DeepFashion2 모델(약 24MB)은 저장소에 없습니다.** 서버가 옷 분류를 처음 요청받을 때
  `backend/models/`에 자동으로 내려받습니다. 첫 요청은 다운로드 때문에 조금 느리고 인터넷이 필요합니다.
- Windows에서 `ultralytics` 설치 중 `cv2` "액세스 거부" 오류가 나면, 이미 설치된 `opencv-python-headless`와
  충돌한 것입니다. 아래 **두 줄을 모두** 실행하세요.
  ```bash
  pip install --no-deps ultralytics ultralytics-thop polars cloudpickle
  pip install torch torchvision matplotlib pyyaml requests scipy psutil
  ```
  (`--no-deps`는 딸린 라이브러리를 설치하지 않는다는 뜻이라, 새 컴퓨터에서는 두 번째 줄로 PyTorch 등을 따로 설치해야 합니다)
- 서버가 꺼져 있어도 앱은 동작합니다. AI 옷 등록에서 종류를 사용자가 직접 고르게 됩니다.

### 2. 앱

- Android Studio로 `fashion_app` 폴더를 열고 실행합니다.
- 서버 주소는 `data/BackendApi.kt`의 `BASE_URL`입니다.
  - 에뮬레이터: `http://10.0.2.2:8000` (기본값)
  - 실기기: `http://<PC의 IP>:8000` (같은 와이파이, PC 방화벽에서 8000 포트 허용)
- 배경 제거(ML Kit)는 **구글 플레이 서비스가 있는 기기**에서 동작합니다. 첫 사용 때 모델을 내려받습니다.
- **날씨 API 키**는 코드에 없습니다. `fashion_app/local.properties`(Git에 안 올라감)에 한 줄을 추가하세요.
  ```
  OWM_API_KEY=발급받은키
  ```
  키가 없어도 앱은 실행되지만 5일 예보와 (서버가 꺼져 있을 때) 현재 날씨를 불러오지 못합니다.
  OpenWeatherMap 무료 키로 충분합니다.


## 수정 사항

### 1. 옷장 데이터 정리
- 흩어져 있던 옷 목록(코드에 고정된 샘플, 메모리에만 있던 옷, 저장된 옷)을 **저장소 하나**(`WardrobeStore`)로 통일
- 옷마다 **고유 번호(id)**, 등록일, 종류·세부 종류·계절을 저장
- 하트(즐겨찾기)가 앱을 껐다 켜도 유지되고, 누른 순서대로 위에 표시
- **샘플 옷 12벌**의 사진을 앱 안(`res/drawable/sample_01~12`)에 넣어 인터넷 없이도 보이게 함
- 처음 실행할 때 샘플 옷을 약 6개월 전에 등록한 것으로 하고 **지난 착용 기록**을 함께 넣음
  → 설치하자마자 달력 · TOP 5 · 안 입는 옷 알림이 보임

### 2. AI 옷 등록 개선
- 처리 순서: **배경 제거 → 옷 종류 분류 → 옷만 오려내기 → 대표 색 추출**
- **배경 제거(누끼)**: ML Kit 피사체 분리, 폰 안에서 동작
- **옷 종류 분류**: 서버의 DeepFashion2 YOLOv8 모델로 13종류(반팔 상의, 긴바지, 치마, 원피스 등) 구분,
  가방류는 기존 COCO 모델로 보완
- 한 사진에 옷이 여러 벌이면 후보들 중에서 직접 선택 가능
- **옷만 오려내기**: 고른 옷의 윤곽만 남겨, 사람이 입은 사진에서도 몸·다른 옷을 지움
- 셔츠·니트처럼 AI가 구분 못 하는 **세부 종류는 직접 선택**, 계절은 규칙으로 자동 지정(수정 가능)
- 대표 색은 **옷 부분만** 보고 계산하고, 색 이름은 색상·채도·밝기 기준으로 판단
- 사진은 갤러리 주소 대신 **앱 폴더에 보관**(원본 · 배경 제거 · 옷만 세 장)

### 3. 옷 상세 · 수정 · 삭제
- 옷장에서 옷을 누르면 **상세 정보창**: 분류 · 계절 · 색, 착용 횟수, 마지막 착용일
- **[정보 수정]**: 등록 화면과 같은 모양으로 사진 종류(옷만/배경 제거/원본), 이름, 카테고리, 종류, 세부 종류, 계절 수정
  (저장해 둔 사진 종류 중에서만 선택)
- **[옷장에서 삭제]**: 확인 후 삭제, 앱 폴더의 사진 파일도 함께 삭제

### 4. 착용 기록 · 달력 · 통계
- 옷장의 **[오늘 입은 옷]**: 입은 옷 여러 벌 선택, 날짜 변경, 한 줄 메모
  (하루에 1건만 기록 — 같은 날짜로 다시 저장하면 수정됨)
- **달력**(옷장의 달력 아이콘): 기록한 날에 점, 날짜를 누르면 그날 코디 · 수정 · 삭제
- **통계**: 이번 달 기록 일수, 가장 많이 입은 옷 TOP 5

### 5. 안 입는 옷 알림 (앱 안에서만 표시)
- 옷장 위 카드: **"3개월 넘게 안 입은 옷이 N벌 있어요"**
- 기준일 = 마지막 착용일 (한 번도 안 입었으면 등록일)
- **지금 계절에 안 맞는 옷은 제외**하고, 제외한 옷은 목록 아래에 따로 안내
- 옷마다 **[정리하기]**(삭제) / **[계속 보관]**(누른 날부터 90일을 다시 셈)

### 6. 가상 피팅 개선
- 옷 사진은 **옷만 → 배경 제거** 순으로 사용, 둘 다 없으면 원본을 쓰고 안내 문구 표시
- 상의 · 아우터 · 하의 · 신발 · 액세서리를 **종류별로 한 벌씩 함께** 겹쳐 입기
- 전신 사진에서 ML Kit 포즈 인식으로 **어깨 · 골반 · 발목**을 찾아 자동으로 맞춤
  (상의 → 어깨, 하의 → 골반, 신발 → 발목, 어깨 기울기 반영)
- 크기 슬라이더와 [−][+], 두 손가락으로 크기·회전, 드래그로 이동, **[몸에 맞추기]** 버튼

### 7. 코디 추천 (계획 4 — 1~3단계)
- **코디 조합 엔진**: AI 학습 없이 **규칙 + 점수**로 옷장 옷을 조합
  - 순서: 오늘 날씨 · 계절(+ 상황)에 안 맞는 옷 빼기 → 상의+하의(또는 원피스)+신발(+필요하면 아우터) 조합 →
    점수 매기기 → 같은 상의 · 하의가 겹치지 않게 골고루 고르기
  - 점수: 색 조합 + 날씨 + 상황 + 착용 기록(최근 2일 안에 입은 옷 감점, 30일 넘게 안 입은 옷 가산) + 스타일 + 내 취향
  - 코디마다 **추천 이유**를 붙임 (예: "블랙 + 베이지는 어디든 어울리는 차분한 조합이에요 · 15도 날씨라 블레이저를 더했어요")
- **색 규칙**: 색상 · 선명도 · 밝기로 판단. 무채색 · 뉴트럴, 톤온톤, 포인트 컬러 1개, 상의 · 하의 밝기 대비는 가산 /
  색이 너무 많거나 선명한 원색끼리 부딪히면 감점
- **날씨 규칙**: 23도 이상 아우터 없음 / 20~22도 얇은 아우터 선택 / 19도 이하 아우터 필요 / 11도 이하 니트 · 코트 우선 /
  비 · 눈이면 밝은 하의 · 흰 신발 감점, 샌들 제외. 계절이 안 맞아도 그날 기온에 맞으면 허용
- **스타일 자동 태그**: 옷 종류 · 색 · 이름으로 미니멀 · 캐주얼 · 클래식 · 스트릿 · 빈티지를 자동으로 붙이고,
  옷 등록 · 수정 화면의 **스타일 칩**으로 바꿀 수 있음
- **신발 세부 종류** 추가: 운동화 → 운동화 · 스니커즈 / 구두 → 로퍼 · 구두 · 힐 (샘플 신발은 스니커즈 · 로퍼로 자동 지정)
- **옷이 부족할 때**: 고정 코디로 대신하지 않고 "코디를 만들려면 하의가 1벌 이상 필요해요" + **[옷 등록하기]** 안내
- **홈 "오늘의 AI 코디"**: 코드에 고정돼 있던 코디 대신 **내 옷장 옷 사진으로 만든 코디** 4개, 카드마다 👍👎
  (👍👎는 지금은 기존 스타일 취향 점수에 반영)
- **상황별 코디**(면접 · 데이트 · 여행 · 운동)
  - 면접: 무채색 · 네이비만, 상의는 셔츠 · 블라우스만, 체크 · 스트라이프 같은 무늬 옷과 청바지 · 운동화 등 제외
  - 데이트: 원피스 · 니트 · 셔츠 가산, 포인트 컬러 1개 가산, 내 취향 점수 2배
  - 여행: 청바지 · 편한 상의 · 운동화 가산, 구두 · 힐 제외, 아우터를 겹쳐 입으면 가산, **여행 날짜를 고르면 그날 예보로 코디**
  - 운동: 반팔티 · 민소매 · 트레이닝팬츠 · 반바지 · 운동화만 (추운 날용 긴팔티 · 후드티 · 점퍼 허용)
  - 맞는 옷이 없으면 "운동 코디를 만들려면 트레이닝팬츠나 반바지, 운동화가 필요해요" 안내
- **5일 예보**: OpenWeatherMap 무료 예보(3시간 간격)를 날짜별로 묶어 최저 · 최고 기온, 비 올 확률, 대표 날씨 계산
  - 코디는 **낮(9~18시) 평균 기온**으로 짜고, 비 올 확률 60% 이상이면 비 오는 날로 봄
  - 일교차 10도 이상인 날은 코디에 겉옷을 넣음
- **미리 알림**(앱 안에서만): 전날보다 5도 이상 추워지거나 더워질 때, 일교차 10도 이상, 비 올 확률 60% 이상
  (예: "내일은 오늘보다 6도 낮아요, 베이지 블레이저 챙기세요")
- **홈 "내일 코디" 카드**: 내일 날씨 · 알림 문구 · 코디 1벌. 홈 🔔에 알림이 있으면 빨간 점, 누르면 "내일 날씨 알림"
- **코디 추천 화면**(홈의 [AI 추천 보기] · [전체보기] · [5일 예보]): 탭 **오늘 / 5일 예보 / 상황별**,
  5일 예보 탭은 날씨 띠에서 날짜를 누르면 그날 알림과 코디
- 위치를 5초 안에 못 받으면 기본 좌표(서울시청)로 날씨를 받음 (에뮬레이터에서 날씨가 계속 "불러오는 중"이던 문제 해결)
- 날씨 API 키를 코드에서 빼고 `local.properties` → `build.gradle.kts`(BuildConfig)로 읽도록 변경

### 8. 서버
- 새 API **`POST /api/clothing/classify`**: 옷 사진 → 옷 종류 후보 목록(크게 잡힌 순) + 옷 윤곽(흑백 PNG, base64)
  - 같은 옷에 이름이 겹쳐 잡히면 확신도가 높은 쪽만 남김
  - 기존 `/api/object-detection`은 그대로 유지
- DeepFashion2 모델 **자동 다운로드** (자세한 내용은 `backend/README.md`)

### 9. DB 연동 (Supabase PostgreSQL)
- 서버가 켜질 때 Supabase에 **테이블 8개**를 자동으로 만들고, 비어 있으면 데모 사용자 · 샘플 옷 12벌 · 상품 8개를 넣음
  (`users`, `clothes`, `wear_logs`, `body_measurements`, `style_ratings`, `products`, `product_likes`, `size_charts`)
- **옷장 · 착용 기록**: 폰에 저장될 때마다 `DbSync`가 전체 목록을 서버로 보내 DB를 똑같이 맞춤 (**폰이 기준**)
  - 옷 등록 · 수정 · 삭제 · 하트 · [계속 보관], 오늘 입은 옷 기록 · 수정 · 삭제가 모두 DB에 반영
  - 서버가 꺼져 있어도 앱은 그대로 동작하고, 다음 변경이나 앱 재실행 때 맞춰짐
- **체형 분석**: 분석이 성공하면 결과 숫자(체형 · 신뢰도 · 비율 · 키 · cm 추정값)를 측정 기록으로 저장 — **사진은 저장 안 함**
- **취향 학습**: 좋아요/싫어요를 한 줄씩 기록하고 점수는 기록으로 다시 계산 (서버를 껐다 켜도 유지)
- **쇼핑 하트**: 서버에 저장 → 앱을 다시 켜도 하트 · 순서 유지
- **마이페이지**: 옷 개수 · 착용 기록 일수 · 하트 개수 · 최근 체형을 DB에서 셈
- **폰마다 따로 저장**: 앱이 처음 실행 때 기기 번호를 만들어 모든 요청에 붙임(`X-Device-Id`) →
  팀원 여러 명이 같은 Supabase DB를 써도 서로의 옷장을 덮어쓰지 않음 (Swagger처럼 번호가 없으면 데모 사용자)
- **사이즈표**: 브랜드 사이즈표를 CSV로 넣는 도구(`import_size_charts.py`)와 조회 API(`/api/size-charts`) — 사이즈 추천 준비
- DB 주소 · API 키는 코드에 없고 `backend/.env`(깃허브에 안 올라감)에서 읽음

### 10. 측정 기록 그래프 · 스타일 분석 · 개인정보 보호
- **체형 측정 기록 · 변화 그래프** (계획 1 — 7번, 새 화면 `BodyHistoryScreen`)
  - 서버 DB에 쌓인 측정 기록을 불러와 **날짜별 꺾은선 그래프** (어깨:엉덩이 · 허리:엉덩이 · 다리 비율, 어깨 · 허리 · 엉덩이 cm 중 선택)
  - 직전 기록과 비교한 한 줄 요약 — 예: "지난번보다 허리:엉덩이 −2%, 허리 너비 −1.2cm", 체형이 바뀌면 함께 안내
  - 측정 오차를 고려해 비율 1% 미만 · cm 0.5cm 미만 차이는 "변화 없음"으로 표시
  - 들어가는 곳: 마이페이지 > 체형 측정 기록 · 변화 그래프 / 체형 분석 화면 아래 링크
- **스타일 분석 화면을 실제 데이터로** (`StyleProfile`)
  - 고정 숫자("미니멀 35%") 대신 **옷장 옷의 스타일 태그 + 최근 90일 착용 기록**으로 계산 (보유 50% + 착용 50%, 기록 없으면 보유만)
  - 키워드는 많은 스타일 순 + 가장 많은 색, 코멘트는 "옷장에는 클래식이 가장 많지만 최근엔 캐주얼을 가장 자주 입었어요"처럼 데이터로 생성
  - 스타일별로 "보유 n벌 · 착용 m회" 표시
- **개인정보 동의 화면** — 체형 촬영 · 사진 선택 전에 한 번 표시, [동의하고 시작]을 눌러야 시작
  - 사진은 폰 안에서만 분석 · 서버에는 숫자만 저장 · 얼굴 인식에 쓰지 않음 · 언제든 삭제 가능 안내
  - **측정 기록 저장은 선택** (끄면 분석 결과도 서버에 남기지 않음)
  - 촬영한 체형 사진(앱 임시 폴더)은 다음 분석 때 자동으로 지움
- **마이페이지 설정**: [개인정보 처리 안내](우리 앱 기준 안내 — 예전엔 구글 개인정보처리방침 링크였음),
  [체형 측정 기록 저장] 켜기/끄기, **[측정 기록 삭제]**(서버 기록 전부 삭제)
- 마이페이지 체형 배지가 고정값("모래시계형") 대신 **최근 분석 결과**를 표시
- 단위 테스트 추가: `StyleProfileTest`(6개), `BodyHistoryAnalyzerTest`(6개)

### 11. 선호 스타일 저장 · 시연 데이터 · 서버 상태 · 성능 측정 · 날씨 알림
- **온보딩 선호 스타일 저장**: [시작하기]를 누르면 고른 스타일을 폰 + 서버 DB(`users.preferred_styles`)에 저장
  - 다음에 온보딩을 열면 예전 선택이 미리 체크됨 (아무것도 안 고르면 예전 선택 유지)
  - 마이페이지 "선호 스타일"이 고정값 대신 실제 선택을 표시
- **시연용 측정 기록 샘플**: 서버가 새 사용자(폰)마다 한 번 지난 3개월치 기록 5개를 넣음 → 변화 그래프가 바로 보임
  - 앱에는 회색 점 · "샘플" 표시로 구분, 측정 기록 화면의 [샘플 지우기]로 지울 수 있음 (지운 샘플은 다시 안 생김)
  - 마이페이지 체형 · 체형 맞춤 제안에는 샘플이 아닌 **실제 측정**만 반영
- **서버 연결 상태 표시** (홈 · 마이페이지): "● 서버 연결됨 · DB 저장 중" / "● 오프라인 · 폰에만 저장", 15초마다 확인, 누르면 바로 확인
- **AI 성능 측정 도구** (`backend/evaluation/`)
  - 체형 cm: 줄자 실측 vs 앱 값을 CSV에 적고 `eval_body.py` → 평균 오차 · 오차율 · ±2cm 이내 비율 · 치우침 · 반복 측정 편차 표
  - 옷 분류: 정답 폴더별 사진을 넣고 `eval_classify.py` → 소분류 · 대분류 정확도, 후보 포함률, 혼동표, 틀린 사진 목록
  - 측정 방법은 `backend/evaluation/README.md`
- **내일 날씨 푸시 알림** (WorkManager)
  - 마이페이지 > 알림 설정에서 켜면 매일 저녁 8시쯤 "내일 맑음 9°/18°" + 홈 "내일 코디"와 같은 규칙의 알림 문구 · 추천 코디를 폰 알림으로 보냄
  - [지금 테스트 알림 보내기] 버튼 (시연용), 안드로이드 13 이상은 알림 권한을 물어봄
  - 저녁에는 오늘 낮 기온을 예보로 알 수 없어서, 미리 받아 둔 낮 기온으로 "오늘보다 몇 도"를 계산 (없으면 기온 비교 문구는 생략)
  - 예전 "알림 설정" 창은 실제로는 아무것도 안 하는 안내문이었음 → 실제 켜기/끄기로 바꿈
- 앱 시작 처리를 `FashionApp`(Application)로 옮김 — 백그라운드 알림 작업 때도 기기 번호가 먼저 준비되도록
- 취향 점수: 서버 기록이 폰보다 적으면(새 서버 · 새 기기 번호) 폰 점수를 덮어쓰지 않도록 수정
- 라이브러리 추가: `androidx.work:work-runtime-ktx:2.9.1` (처음 빌드할 때 Gradle Sync 필요)

## 알려진 한계 · 주의사항

- **세부 종류**(셔츠/니트 등)는 AI가 구분하지 못해 사용자가 고름.
- 옷만 오려내기에서 옷 위에 겹친 손 · 머리카락이 남을 수 있음.
- 가상 피팅은 사진을 겹쳐 올리는 방식이라 옷이 몸 모양대로 휘지 않고, 맞추는 비율은 대략값.
  정면 전신 사진이어야 몸 위치를 잘 찾음.
- 신발 · 액세서리는 자동 분류되지 않음(가방류만 가능).
- **DeepFashion2 학습 데이터는 비상업 연구용**이라 캡스톤 시연 용도로만 사용 가능.
  모델 출처: 허깅페이스 [Bingsu/adetailer](https://huggingface.co/Bingsu/adetailer) (`deepfashion2_yolov8s-seg.pt`)
- 옷장 · 착용 기록은 **폰 → 서버 한 방향**으로만 동기화됨 (폰을 바꾸면 서버에서 다시 받아오는 기능은 아직 없음).
- 로그인 대신 **기기 번호**(앱이 처음 실행 때 만듦)로 사용자를 구분함 → 앱을 지우고 다시 설치하면 새 사용자가 됨.
- 옷 사진 파일은 서버에 올리지 않고 폰 안의 주소만 저장함.
- 코디 추천의 색 규칙 · 점수 기준값은 초기값이라 실제 코디를 보면서 조정이 필요함.
- 옷의 대표 색 1개만 사용 → 줄무늬 · 체크 같은 무늬는 색 판단에 반영되지 않음.
- 옷장에 옷이 적으면 코디가 나오지 않음 ("옷이 부족해요" 안내가 나옴).
- 예보는 무료 범위인 **최대 5일**.
