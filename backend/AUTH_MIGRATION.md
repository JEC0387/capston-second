# 개인 데이터 인증 전환 (P0)

개인 DB API는 이제 `Authorization: Bearer <접속 토큰>`이 필요합니다. `X-Device-Id`만으로는 옷장·사진·체형·취향·백업 데이터를 읽거나 바꿀 수 없습니다. 접속 토큰과 복구 코드는 각각 256비트 무작위 값이며 서버에는 SHA-256 해시만 저장합니다. 앱은 이를 비공개 저장소에 보관하고 Android 자동 백업에서 제외하며 HTTPS에서만 전송합니다.

## 운영 적용 전

이 브랜치는 운영 DB와 Railway에 적용하지 않았습니다. 운영자 승인 후 먼저 `005_auth_credentials.sql`을 적용하고, 개인정보 API가 인증 없는 요청을 거절하는지 확인한 다음 `AUTH_REGISTRATION_ENABLED=true`를 설정해야 합니다. 앱과 서버를 서로 다른 버전으로 배포하면 기존 앱의 서버 백업은 동작하지 않습니다. 사진·체형 숫자 등 폰의 로컬 기록은 지워지지 않습니다.

## 새 설치와 복구

- 새 설치는 첫 동기화 또는 백업 화면 진입 시 빈 계정을 발급받습니다. 복구 코드를 안전하게 보관해야 다른 폰에서 복원할 수 있습니다.
- 새 폰에서 복구 코드를 입력하면 기존 접속 토큰은 폐기됩니다. 복원 전에는 동기화를 멈춰 새 폰의 대기열이 기존 기록을 덮지 않도록 합니다. 복원 중 오류가 나면 로컬 기록을 덮지 않고 다시 시도합니다.
- 코드 분실 시 서버 기록의 자동 복원은 보장하지 않습니다. 폰 안의 기록은 계속 사용할 수 있습니다.

## 기존 기기 번호 데이터

기존 `device_id`와 서버의 사용자·옷장·사진·체형 기록은 그대로 둡니다. 이전 앱 설치는 자동 동기화를 멈추고 두 선택지를 보여 줍니다.

1. 기존 서버 기록을 이전하려면 운영자가 **기기 번호 외의 독립적인 증빙**으로 소유권을 확인합니다. 확인 방법과 승인 기록은 운영 절차로 별도 정해야 합니다. 확인 후 운영자가 비공개 환경에서 `python auth_admin.py --device-id <옛 기기 번호> --verified-out-of-band`로 24시간짜리 일회용 승인 코드를 발급해 사용자에게 안전하게 전달합니다. 승인 코드는 저장소·로그·공개 채팅에 넣지 않습니다. 앱에서 승인 코드를 입력하면 새 인증을 기존 사용자 행에 연결하고, 기존 행과 데이터는 이동·삭제하지 않습니다. 복원을 마치기 전에는 동기화가 재개되지 않습니다.
2. 사용자가 이 폰의 로컬 기록으로 새 계정을 명시적으로 시작할 수 있습니다. 예전 서버 데이터는 귀속·삭제되지 않으며, 새 계정에 로컬 기록을 올리는 선택입니다.

옛 기기 번호만으로 승인 코드를 발급하면 안전한 소유권 확인이 **아닙니다**. 독립적 확인 절차가 마련되지 않았다면 레거시 클라우드 이전은 보류해야 합니다. 운영 DB 변경·승인 코드 발급·실제 배포는 별도 승인 후 수행합니다.
