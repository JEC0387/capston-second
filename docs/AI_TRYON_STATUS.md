# AI 가상피팅 구현·검증 상태

## 기존 문제와 변경

- 기존 `VirtualFittingScreen`은 옷 이미지를 전신 사진 위에 그리는 수동 캔버스다. 마법봉은 ML Kit 관절 위치를 기준으로 배치·크기·회전을 초기화했으며 FASHN을 호출하지 않았다. 사각형 배경이 있는 상품은 배경도 겹쳐 보였다.
- 실제 FASHN 호출은 별도 `MusinsaClosetScreen.TryOnView`에만 있었고, 내 옷장 화면과 연결되지 않았다.
- 수동 이동/확대/회전/투명도/옷별 조절을 보존하고 자동 정렬 아이콘·접근성 이름을 `수동 배치 초기화 · 관절 위치에 맞추기`로 구분했다. 수동 기능이 AI 합성이라는 문구를 제거했다.
- 내 옷장의 `AI로 입어보기`(마법봉)는 선택한 옷의 스냅샷과 원본 전신 사진으로 `AiTryOnScreen`을 연다. 이 화면의 생성 버튼은 `TryOnRepository.tryOn`으로 연결된다. 수동 드래그 좌표·회전·투명도는 API 입력이 아니며 결과에 반영된다고 안내하지 않는다.
- AI 미설정/입력 준비/생성 중/실패/성공을 구분한다. 실제 API 결과 URL이 와야만 성공한다. 실패 시 옷 선택은 그대로이며 재시도마다 새 전송 동의를 받는다. 원본 비교와 시스템 문서 선택기를 통한 JPEG 결과 저장을 추가했다.
- 무신사의 기존 상품/구매 UI는 보존하고, 같은 순차 생성 검증과 결과 저장을 적용했다. 미설정이어도 안내 화면 진입이 가능하다.

## API·지원 범위와 비용

기존 구현의 FASHN `tryon-v1.6`, `POST https://api.fashn.ai/v1/run`, `GET /v1/status/{id}` 프로토콜을 유지했다. category는 tops / bottoms / one-pieces이며 앱에서 상의·아우터 / 하의 / 원피스에 대응한다. 신발·액세서리는 생성하지 않고 제외 안내한다. 상의와 아우터 동시 선택, 원피스와 다른 지원 의류 동시 선택은 사용자에게 선택을 정리하도록 안내한다.

- 상의 또는 하의 한 벌: 생성 POST 최대 1회.
- 상의(또는 아우터)+하의: 상의 결과 URL을 다음 인물 입력으로 전달하는 순차 생성 POST 최대 2회. 한 번에 두 벌을 생성하는 모델이라고 가정하지 않는다.
- 각 작업의 상태 polling은 생성 POST와 구분한다. 생성 POST 자동 재시도는 하지 않는다. 앞 단계 실패 시 다음 생성도 하지 않는다. 중간 결과만 성공으로 표시하지 않는다.
- 재시도는 추가 유료 요청이다. 실제 요금·차감 크레딧·성공/실패 과금은 현재 계정/서비스 정책을 확인해야 한다. 과거의 '무조건 1벌=1크레딧' 문구를 확정 가격으로 유지하지 않았다.
- 여러 번 생성하면 얼굴·체형·의상 세부 유지가 더 어려워질 수 있다. 실제 제품 핏·구매 사이즈·얼굴 동일성은 보장하지 않는다.

## 개인정보·보안

사진은 버튼을 누른 것만으로 전송하지 않는다. 전송 대상/목적/순차 요청 횟수/중간 결과 재전송/유료 요청/결과 한계 안내를 확인한 뒤 한 번만 승인한다. 거부하면 전송하지 않고 수동 배치를 유지한다. 체형분석 이용 동의·기록 저장 동의와 별개다. 체형분석 경로에는 FASHN 호출을 추가하지 않았다.

`FASHN_API_KEY`는 기존처럼 Git에서 제외된 local.properties를 통해 BuildConfig에 들어간다. GitHub Actions APK에는 키를 주입하지 않으므로 AI 생성은 미설정 상태가 정상이며 기기 내 체형분석과 수동 피팅은 사용할 수 있다. 실제 키를 로그/문서/응답에 쓰지 않는다. BuildConfig 키는 APK에서 추출될 수 있는 기존 위험이 남는다. Backend에 기존 FASHN proxy는 없으며, 서버 자격증명·인증/속도 제한 인프라 없이 새 운영 proxy 배포를 완료했다고 주장하지 않는다.

HTTP 자동 redirect를 끄고 finally에서 연결을 해제한다. 불특정 서버 원문 오류는 사용자 화면에 그대로 출력하지 않는다. 결과는 HTTPS URL만 허용한다. 준비 비트맵은 EXIF 방향 처리/리사이즈 후 해제한다. 결과 저장은 JPEG 확인·20MB 제한과 시스템 문서 선택기를 사용하며 광범위 저장 권한을 추가하지 않는다. 화면 취소는 이미 서버에 접수된 작업·과금을 취소한다고 보장하지 않는다.

## 실제 검증과 미검증

순수 Kotlin 계획/순차 실행 테스트 14개를 추가했다. 지원/제외/충돌, 호출 순서·횟수, 첫 결과를 다음 입력으로 사용, 실패 시 중단·자동 재시도 없음, 취소 후 다음 요청 방지, 빈 결과/안전하지 않은 URL 거부를 가짜 제공자로 검증한다. 이 테스트는 유료 API를 호출하지 않는다.

최초 컴파일에서 타임아웃 람다의 return 레이블 오류 1개가 발생했고 올바른 레이블/반환 구조로 수정했다. 수정 후 전체 테스트와 Android 컴파일 결과는 REAL_DEVICE_FIX_HANDOFF.md를 따른다.

실제 FASHN 계정/크레딧/유료 생성, API 요청·응답의 현행 서비스 호환성, 생성 품질·얼굴 보존, 실제 폰의 EXIF/네트워크/파일 저장은 **미검증**이다. 공식 문서 https://docs.fashn.ai/api-reference/tryon-v1-6 접근은 이 환경의 proxy CONNECT 403으로 실패했으므로 현행 요금/모델 지원을 새로 확인했다고 주장하지 않는다. 유료 호출 승인 없이 비용이 발생하는 검증을 수행하지 않았다. 현재 구현은 기존 API 경로를 재사용하는 클라이언트 연결이며 실서비스 연동 성공을 의미하지 않는다.


## 발표 전 공식 문서 검토 (2026-10-18)

공식 https://docs.fashn.ai/api-reference/tryon-v1-6 를 실제 열람했다. model_name/inputs 안의 model_image, garment_image, category, mode, output_format 구조와 URL/data URI 입력이 현재 문서와 일치한다. 지원 category는 auto/tops/bottoms/one-pieces이며 이 앱은 기존 명시적 카테고리만 사용한다. flat-lay·ghost mannequin·on-model 상품 이미지를 문서가 다루며 garment_photo_type의 기본은 auto다. 앱은 원본 상품 사진을 우선 전달하고 수동 드래그 좌표는 보내지 않는다. 원본에 배경이 있어도 전송하며 실제 추론 결과를 검증한 것은 아니다.

문서상 처리 해상도는864×1296이며 현재 클라이언트는 긴 변1296 이내 JPEG를 준비한다. 실제 입력 사진이 제공되지 않아 포즈·가림·옷 디자인/배경 조건을 만족하는지 검증하지 않았다. 모델 교체나 자동 배경 제거 기능을 새로 만들지 않았다. v1.6 신발·액세서리를 지원한다고 표시하지 않으며 Try-On Max 같은 별도 유료 모델로 바꾸지 않았다.

문서상 결과 이미지1장당1크레딧이고 num_samples 기본1이다. 앱도 num_samples=1을 명시해 기존 단일 결과 의도를 고정했다. 상의+하의 성공 시 중간1장+최종1장으로2개의 생성 출력이 생긴다. 실제 계정 가격/실패 시 과금/크레딧은 조회하지 않았고 유료 호출은0회다. 생성 시도는 여전히 사진별 별도 동의 후에만 가능하다. 키 존재가 인증/크레딧 유효성을 증명하지 않으며401·402·통신 실패를 성공으로 처리하지 않는다.

미설정 시 자연스럽게 옷을 생성한다고 약속하는 안내를 표시하지 않고 수동 배치/연결 안내를 제공한다. 좁은 수동 화면은 조절 패널만 높이를 제한해 스크롤하고 인물 캔버스의 드래그와 분리한다. 생성 결과 비교/저장과 API 실호출은 여전히 실기기·유료 미검증이다.
