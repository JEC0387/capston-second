# P2 피팅 경로·제공 방식 검토 — 2026-10-25

## 코드에서 확인한 원인과 범위

- `VirtualFittingScreen`의 수동 캔버스는 의류 이미지를 이동·크기·회전·투명도로 배치한다.
  관절 정렬은 배치 초기화다. 조명/주름/가림을 생성하지 않아 붙인 듯한 인상이 생길 수 있다.
- `VirtualFittingScreen`과 `MusinsaClosetScreen`의 실제 AI 진입점은 공통 `AiTryOnScreen` →
  `TryOnViewModel` → 인증된 FastAPI 프록시 → FASHN이다. 수동 캔버스 스크린샷이나 배치 좌표를
  생성 입력으로 쓰지 않는다. AI 실패 시 수동 합성을 AI 결과로 바꾸는 코드는 없다.
- 원본보다 작은 결과, 반복 JPEG 압축, 잘린 인물/의류·방향 오류·가림·복잡한 배경은 입력/출력
  경로에서 다룰 수 있다. 얼굴·원래 체형·목선·팔 가림·피부 경계·주름·그림자 생성은 모델의
  역할이다. 전처리나 화면 확대만으로 이 문제를 해결했다고 주장하지 않는다.
- 여러 벌을 순차 생성하면 앞 생성의 변형이 누적될 수 있다. 요청 횟수 제한·단일 생성·동의·
  중간 결과 재전송 안내를 유지했다. 중간 이미지 한 장을 전체 성공으로 표시하지 않는다.

## 이번 구현

- 인물용 상반신/전신과 의류용 입력 검사, 기기 내 자세 검사를 유료 요청 전에 수행한다.
  잘림·낮은 검출 가시성·기울기·작은 해상도·과대 이미지는 거절한다. 이는 촬영 휴리스틱이며
  사람 식별이나 생성 품질 예측, 정확도 수치가 아니다. 의류 배경 경고도 객체 분할 결과가 아니다.
- EXIF 방향과 원래 비율을 유지해 축소하고 위치 메타데이터를 제거한다. 배경/옷을 임의로 잘라내지
  않으며 투명 의류는 흰 배경으로 변환한다. 지원되는 경로에서 애니메이션을 거절한다.
- 기존 v1.6 모델의 공식 `quality` 모드를 사용하고 출력 수는 1개로 고정했다. 모델 교체·
  자동 재생성은 없다. 서버 결과 재처리는 입력용 1296px 제한 대신 최대 2048px/JPEG95로
  추가 손실을 줄인다. 원본 모델 출력보다 디테일을 만들어 내거나 업스케일하지 않는다.
- 원본/AI 결과 같은 배율 전환, 1~4배 확대·이동·초기화, 이전 결과 명시, 상세 오류·입력 힌트를
  추가했다. 재생성 실패 때 보존된 이전 결과를 이번 생성의 성공처럼 안내하지 않는다.

## 문서 기반 대안 비교 — 실제 시각 품질 순위 아님

공식 자료를 열람했으며 유료 생성/크레딧 조회/가중치 다운로드/실제 모델 실행은 하지 않았다.
동일 입력의 얼굴·체형·의상 보존과 자연스러움은 아래 모든 방식에서 **미검증**이다.

| 방식 | 품질·속도·비용 관점 | Android/FastAPI·개인정보 관점 |
|---|---|---|
| FASHN v1.6 유지 | 공식 문서에 quality 모드, 출력당 1 credit, 대표 처리시간 12~17초 안내. 이 앱의 실제 지연/차감은 미측정 | 기존 프록시 재사용. 별도 키를 앱에 넣지 않고 base64·인증 결과 경로 유지 |
| FASHN Try-On Max | 제공자는 고해상도/제품 보존을 강조하지만 비교 실험 없음. 문서상 quality는 해상도별 3~5 credits로 v1.6과 비용 구조가 다름 | product_image/해상도 등 별도 요청·제한·동의·예산 검증 필요. 이번에 전환하지 않음 |
| IDM-VTON 자체 호스팅 | 논문의 디자인 보존 목표를 참고할 수 있으나 이 데이터에서 우수하다고 판단할 수 없음. GPU 운영비·지연 실측 필요 | 프록시 뒤 GPU 추론·마스크/포즈 전처리·보안 운영 필요. 코드/가중치의 CC BY-NC-SA 4.0 조건과 전처리 의존성 확인 필요 |
| CatVTON 자체 호스팅 | 저자 저장소는 1024×768에서 8GB 미만 VRAM 추론을 설명. 실제 기기/서버 비용·품질 미측정 | Android 직접 실행으로 가정하지 않고 GPU 서버 검토. CC BY-NC-SA 4.0 및 기반 모델 조건 검토 필요 |

가격은 credit 기준 설명이며 실제 통화 가격·현재 계정 조건·실패 과금은 확인하지 않았다.
자체 호스팅도 무료 운영을 뜻하지 않는다. 라이선스 적합성 확인 전 제품용 대체 모델로 채택하지 않는다.

## 전송·보관 정책 확인

[공식 보관 정책](https://docs.fashn.ai/api-overview/data-retention-privacy)은 base64 입력을
처리 중 임시 사용하고 완료 후 삭제하되 하루 정리를 안전장치로 두며, base64 출력을 완료 후
60분 제공한다고 설명한다. 요청 이력은 자동 삭제하지 않는다고 명시한다. 앱 서버의 RAM 결과
보관 30분과 외부 제공자의 보관을 구분해 동의 문구를 보완했다. 학습 미사용에 관한 공식 정책은
별도 약정 예외가 있으므로 앱이 제3자 처리를 무조건 보장하지 않는다. 실제 계정/약관 적용은 후속 확인한다.

## 승인 후 남은 시각 품질 평가

동의받은 동일 인물/의류로 이전 설정과 새 설정을 짝지어 평가한다. 얼굴·체형·배경 보존,
목/어깨/팔 가림, 허리/골반 실루엣, 색/패턴, 주름/조명/피부 경계를 구분해 기록한다.
복수 관찰자 평가와 지연·차감 기록을 남기고 실패도 포함한다. 단일 사진 비교를 정확도나
우수성 백분율로 만들지 않는다. 사용자 사진·생성 결과는 Git/로그에 넣지 않는다.

실제 생성·얼굴 동일성·옷 디자인 보존·실제 착용 핏·비용은 이번 자동 테스트로 입증되지 않는다.
입력 자세 검출과 실제 터치 확대·갤러리·EXIF 기기 동작도 사용자의 후속 실기기 검증 대상이다.
