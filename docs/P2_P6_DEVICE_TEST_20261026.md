작성일: 2026-10-26 KST. 이 문서는 실행 결과가 아니다. 아래 실기기 항목은 모두 미검증이다.

## APK 받기와 기존 데이터 보존

1. 최종 성공한 GitHub Actions에서 `fashion-app-debug-apk`를 받는다. 코드 SHA는 최신 인수인계와
   `BUILD_INFO.txt`를 대조한다. 중간에 취소된 실행이나 다른 저장소의 APK를 섞지 않는다.
2. 압축 안의 `fashion-app-debug.apk`, `SHA256SUMS.txt`, `BUILD_INFO.txt`를 함께 보관한다.
   Linux/macOS는 적절한 SHA-256 도구로, Windows는 `Get-FileHash .\fashion-app-debug.apk -Algorithm SHA256`으로
   체크섬을 대조한다. 아티팩트 zip의 digest와 내부 APK 파일의 체크섬은 서로 다른 값이다.
3. 패키지 `com.jeiu.fashionproject`, 기기 Android 버전, 기존 앱의 서명·데이터 보존 가능성을 확인한다.
   기존 앱이 있다면 동일한 서명 APK로 업데이트한다. 로컬 Debug 키와 Actions의 Debug 키가
   다를 수 있으므로 기존 APK의 서명과 비교한다. 기기의 현재 기록·사진·복구 수단을 먼저 보존한다.
4. 설치는 시스템의 업데이트 설치나 확인된 환경에서 `adb install -r fashion-app-debug.apk`를 사용한다.
   서명 불일치/버전 충돌 시 중단한다. 앱 삭제, `pm clear`, `adb uninstall`, 강제 다운그레이드로
   우회하지 않는다. 키스토어나 복구 코드·개인 사진을 공개 로그/이슈에 올리지 않는다.
5. APK 빌드/서명 검사는 실제 기기 설치 성공이나 화면·GPU 정상 동작의 증거가 아니다.

## 실제 AI 피팅은 별도 조건 필요

- 운영 API 키를 앱에 넣지 않는다. 기존 개인 프록시 토큰·HTTPS·전송 동의를 유지한다.
- 실제 FASHN 계정에 연결된 상태에서 `확인하고 AI 생성`을 누르면 유료 요청이 될 수 있다.
  실기기 설치 테스트가 유료 호출 승인까지 의미하지 않는다. 승인 전에는 실제 생성하지 않는다.
- 무료 확인은 인증된 HTTPS 모의 서버/가짜 제공자가 준비된 경우에만 입력·진행·실패·비교·저장을
  확인한다. 그러한 기기용 모의 서버를 이번 작업에서 배포하지 않았다. 자동 테스트는 격리 가짜 제공자를 사용했다.
- 실제 모델 품질 평가를 승인하면 동일 인물/의류 쌍으로 얼굴·체형·목/어깨·팔 가림·피부 경계·
  패턴/색·주름/조명·배경을 비교하고 비용·지연을 기록한다. [모델 검토](P2_PROVIDER_REVIEW_20261025.md) 참고.
- 이전 결과/이번 결과 구분, 같은 배율 확대, 중복 클릭/화면 이동/응답 손실 시 생성 POST가
  반복되지 않는지 확인한다. 생성 실패를 수동 합성 성공으로 처리하지 않아야 한다.
- 사진·치수·접속 토큰·원본 URL·생성 이미지를 Git이나 공개 보고서에 넣지 않는다.
