# P69 체형 기록 계정 소유권 수정

기준: a63d612365ceed30120e465c69bb116278d81a22 (18629).

## 원인과 변경

기존 `account_<SHA256(server + token)>_` 키는 토큰 복구/소셜 로그인으로
토큰이 교체되면 같은 계정의 기록에도 접근하지 못한다.

새 키는 `account_v2_<SHA256(server + accountId)>_`이다. `accountId`는
인증된 서버의 `AuthCredential.user_id`에서만 얻으며 사용자 입력, 이메일,
장치 ID 또는 소셜 로그인 화면 메타데이터로 만들지 않는다. 인증 API의
응답에 문자열 `accountId`를 추가한다. 기존 클라이언트 계약은 유지하고
DB 스키마/마이그레이션은 변경하지 않는다.

ID와 이전 토큰 범위의 소유권 증거는 기존 암호화 CredentialVault에
보존한다. 현재 로그인·서버와 일치하고 복원 차단이 해제된 계정만 읽는다.
로그아웃/계정 변경/인증 무효화 때 화면 메모리의 체형 정보도 다시 읽는다.

## 이전 규칙

- 인증된 응답으로 소유권을 확인한 **해당 토큰 범위만** 복사한다.
- 3D 프로필, 기존 프로필 백업, 실측값의 원본 키는 삭제하지 않는다.
- 게스트 기록과 다른 계정 기록은 자동 이전하지 않는다.
- 기존 목적지 기록이 있으면 덮어쓰지 않는다.
- 서로 다른 옛 기록이 여럿이면 임의로 선택하지 않고 원본을 보존한다.
- 쓰기 실패를 저장 성공으로 처리하지 않고, 새 복사본만 보상 처리한다.
- 유효한 옛 토큰에 기록이 있으면 복구/소셜 전환 **전** 읽기 전용 인증
  조회로 소유권을 확보한다. 조회 실패를 인증 우회 근거로 쓰지 않는다.

## 배포 의존성과 한계

운영 서버는 이 작업에서 변경하지 않는다. 담당자가 서버 응답의
`accountId` 추가를 반영해야 운영 계정의 안정된 저장 키가 활성화된다.
구형 서버에서는 동일한 기존 토큰의 P69 키만 그대로 사용할 수 있다.
따라서 서버 반영 전에는 운영 환경의 토큰 교체 문제가 완전히 해결됐다고
판정할 수 없다. 서버 반영 후 기존 세션을 검증한 다음 계정 전환을 확인한다.

이미 만료/분실된 옛 토큰에만 연결되고 소유권 증거가 전혀 없는 기록은
새 계정에 자동 귀속하지 않는다. 원본은 보존되지만 자동 복원은 보류된다.
운영 DB 초기화, 다른 앱의 토큰 복사, 임의 계정 연결로 해결하지 않는다.

사진 분석 기록, 옷장, 피팅 및 Genlook 요청 경로와 UI 레이아웃은 변경하지
않는다. `BodyAccountOwnershipTest`는 실 SharedPreferences·암호화 저장소와
로컬 HTTPS 인증 응답으로 이전, 복구, 계정 격리, 재시작, 쓰기 실패를 검사한다.
이는 운영 로그인·실기기 업데이트·유료 AI 생성 검증의 대체가 아니다.
