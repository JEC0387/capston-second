# P44 Android 인수 조건 검수

2026-11-06 KST. 이 문서는 P44의 Android 읽기 전용 검수다. 모델 실험 결과는 총괄 실험 기록을 따른다. Android 실행 코드, 기존 APK, 사용자 데이터는 변경하지 않았다. 기기/ADB 접근, Git 작업, 새 Gradle 실행, 전체 CI, APK 생성/설치, 외부 사진 전송은 수행하지 않았다.

## 확인한 실행 계약

검토 파일은 `OnDeviceVtonEngine.kt`, `OnDeviceVtonImages.kt`, `OnDeviceVtonViewModel.kt`, `OnDeviceVtonScreen.kt`다.

- 기본 엔진은 여전히 `UnavailableDeviceVtonEngine`이다. 실제 Android 모델과 런타임 없이 `Ready`를 반환하거나 2D PNG를 생성형 결과로 돌려주는 경로가 없다.
- 생성 버튼은 동의, 유효한 모델 메타데이터, 서로 다른 상의/하의/신발 3종, 인물 사진, 진행 중 요청/저장 없음 조건을 요구한다. 상의/하의만 지원하는 FASHN을 3종 엔진으로 등록할 수 없다.
- 요청 시 선택 목록/배치 키/모델 설정/이미지 바이트를 고정한다. 전처리는 JPEG/PNG, 크기/픽셀 수, EXIF 방향을 검사한다. 결과 수신은 작업 ID, 입력 digest, 모델 SHA, 전체 카테고리, PNG CRC/실제 디코딩을 확인하며 입력 원본 복사 결과를 거절한다.
- 변경된 의류 선택에는 이전 결과를 숨긴다. 실패/취소 후 보존된 결과에는 이전 요청임을 표시한다. 이미지 파일을 다시 열어도 새 생성이라고 표시하지 않는다.
- 취소와 시간 초과는 취소 요청이다. 실제 코루틴/연결된 native 작업이 반환하기 전에 실행 잠금을 해제하지 않는다. 어댑터가 별도 native 작업을 남기지 않아야 하는 계약도 유지한다.
- 저장 선택기가 열린 동안 의류가 바뀌어도 `DeviceSaveTicket`에 고정된 원래 PNG를 저장한다. SAF 실패/취소는 성공으로 표시하지 않으며 부분 파일 가능성을 안내한다. 임의 삭제는 하지 않는다.

현재 연결된 `Unavailable` 경로에서 새로 재현할 수 있는 production 결함은 발견하지 못했다. 따라서 실행 코드를 변경하거나 같은 자동 검사를 반복하지 않았다. 수신 계약과 PNG 검증은 **실제 생성형 추론의 증명이나 자연스러움 판정이 아니다**. 실제 어댑터/모델 실행 증거가 별도로 필요하다.

## 기존 자동 검사 재사용의 근거

P39 `ui03/start.json`의 소스 목록 10개와 현재 파일의 SHA256을 비교하여 **10개 일치 / 0개 불일치**를 확인했다. 이는 Android 전체 프로젝트 해시 검사가 아니라 해당 목록의 비교다.

기존 `focused02/xml`에서 최초 실패한 UI 클래스는 제외하고, 최종 `ui03/xml`의 해당 클래스 결과를 사용했다. XML 재확인 결과는 고유 **47 PASS / 0 failure / 0 error / 0 skipped**다. 최초 UI 실패 3건은 원본 증거에 남아 있다. 새 테스트 실행 횟수는 0회다.

| 기존 검사 | 최종 고유 통과 | 근거 |
|---|---:|---|
| 요청/선택 전달 | 3 | P39FittingHandoffTest, focused02 |
| 상태/취소/응답 계약 | 6 | P39OnDeviceControllerTest, focused02 |
| 이미지/EXIF/저장 | 12 | P39OnDeviceImagesTest, focused02 |
| 모의 엔진 UI | 5 | P39OnDeviceVtonUiTest, ui03 |
| 기존 피팅/아바타 | 10 | PresentationFittingUiTest, focused02 |
| 드래그 상태/UI | 7 + 3 | P36DragStateTest/P36DragUiTest, focused02 |
| 사진 리사이즈 UI | 1 | P22PhotoResizeUiTest, focused02 |

기존 Lint 기록은 오류 0 / 경고 179 / Hint 2다. 이는 P39 소스의 기존 검증이며 P44 전체 빌드나 실제 모델 연결 검증으로 세지 않는다.

## APK와 설치본의 구분

로컬 파일 존재/크기를 읽기 전용으로 확인했다. 아래 SHA256은 P42 `experiments/P42-20261106/LOCAL_CHECKPOINT.json`의 기존 검증값을 재사용했으며 이번 검수에서 APK를 다시 해시하거나 서명을 재검사하지 않았다.

Preview 18605/QA 18607 설치 상태는 기존 인수 기록이다. 이번에 기기에서 다시 조회하지 않았다. 두 APK는 P39 이전 실행 코드이므로 이 설치본으로 P39/P44 온디바이스 마법봉을 검증했다고 보고할 수 없다. 새로운 데이터 해시 비교도 하지 않았으므로 기기 전체 데이터 보존을 새로 검증한 것으로 확대하지 않는다.

## 실제 엔진 통합 전 남은 게이트

1. 상의/하의/신발 전체를 처리하는 실제 실행 자산과 모든 구성요소의 허용된 배포 권리.
2. 전체 모델/전처리/샘플러 Android 런타임의 원본 수치 비교. 부분 ONNX 블록 성공은 전체 모델 변환 성공이 아니다.
3. 동적 엔진을 도입할 때 `issueFor` 이후 두 번째 availability 조회 간 모델 교체/해제 경합을 막는 원자적 모델 스냅샷과, 여러 ViewModel 간 native 작업의 단일 실행/실제 종료 보장. 현재 고정 `Unavailable` 경로에서는 이 경합이 발생하지 않는다.
4. 버전별 설치 승인 후 S25+ 실제 모델 로딩, 메모리/시간/취소/백그라운드 복귀 검증. 새 생성 이미지에 대한 자연스러움·얼굴/배경 보존·세 카테고리 일치 검수.
5. 실결과 비교 → PNG 저장 → 앱 재실행 → 명시 저장 파일 재열기. 현재 미저장 결과/진행 작업의 프로세스 종료 후 복원은 지원하지 않는다.
6. SAF 저장의 원자성 한계 및 `content://` 제공자가 클라우드에서 파일을 가져올 수 있는 한계를 유지하여 설명한다. HTTP 업로드 코드가 없다는 사실을 앱 전체 네트워크 사용 0회로 표현하지 않는다.

| 인수 항목 | 상태 | 이번 근거/한계 |
|---|---|---|
| 모델 미준비 차단/입력 고정/취소/저장 계약 | TESTED (기존 모의 검사) | 소스 해시 및 기존 XML 재검수 |
| 새로 발견된 Android 실행 결함 | 미발견 | 위 네 파일의 읽기 검수 범위 |
| 실제 생성형 3종 엔진 연결 | BLOCKED | 승인된 전체 Android 실행 엔진 없음 |
| S25+ 모델 로딩/추론/실결과 저장 | NOT TESTED | 기기 접근/설치 없음 |
| 실사진 자연스러움 | NOT TESTED | 모의 PNG/단계 진단 결과로 대체 불가 |
| 기기 사용자 데이터의 새 보존 비교 | NOT TESTED | 데이터 접근/변경 없음 |
| 정식 출시 | **NO-GO** | 전체 생성, 품질, Android 실실행 및 권리 게이트 미충족 |

본 검수는 새 APK 제작 사유가 아니다. 실제 모델 어댑터 변경이 생기면 관련 P39 상태/이미지/UI 검사와 기존 피팅·드래그 회귀를 단일 담당자가 실행하고, 그 최종 코드의 APK 및 승인된 실기기 검증을 별도로 수행해야 한다.
