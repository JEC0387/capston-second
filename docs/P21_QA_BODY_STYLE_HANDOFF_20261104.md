## 완료한 코드·APK 검토

총괄 1명이 기기 상태 확인을 담당했고, 읽기 전용 하위 담당 1명이 전송·동기화·품질·결과 전달 경로를 검토했다. 앱 코드 수정이나 Gradle/전체 CI 재실행은 없다.

- 기존 QA APK의 내장 identity: `18001`, 실행 SHA `fe68edbbc6e25f95e1389a289044df2a2637c1a2`, `preview=true`, `deviceQa=true`.
- `build.gradle.kts`는 QA에 Preview 격리를 강제한다. `DbSync.isEnabled` 및 enqueue/flush는 Preview에서 비활성이고, `BackendApi` 개인 데이터 경로와 `DataAuth` 운영 등록/복구도 차단된다.
- `BodyAnalysisViewModel`: 로컬 디코딩 → 이미지 품질 → ML Kit 자세 → 자세 품질 → 번들 MediaPipe 실루엣 → 분류/cm 판정. Partial/실패는 성공 결과로 대체하지 않는다.
- 사진 선택 콜백은 동의가 있으면 즉시 분석한다. 키 100~230cm가 필요하며 기존 QA 합성/저장 키를 이번 인물의 실제 키로 가정하지 않는다. 사용자가 직접 확인한다.
- 갤러리 URI 원본은 삭제하지 않는다. 기존 앱 정책상 오래된 앱 캐시 촬영물 정리 경로는 존재하며, 이는 원본 갤러리/Preview 데이터와 별개다. 이번 단계에서 분석을 실행하거나 캐시 정리를 새로 검증하지 않았다.
- 유효 결과는 `BodyAnalysisCompletion`의 메모리 세션에 전달된다. QA에서 서버 저장 동의가 남아 있어도 enqueue가 차단되므로 분석 성공을 영구 서버 기록 저장 성공으로 보고하지 않는다.
- `AppNavigation`은 같은 분석 ViewModel 상태를 스타일 화면에 전달한다. `BodyStyleSuggestions`는 Success와 기존 품질·일관성 검사를 통과한 경우만 개인화한다.
- 스타일 화면의 공개 카탈로그 이미지 네트워크 로드는 가능하다. 개인 사진/분석 결과 전송과 구분하며 SDK 텔레메트리까지 패킷 검증한 것은 아니다.

## 개인정보를 내보내지 않는 검사 경계

- 기존 P20 UI 도구는 전체 XML/화면을 PC에 저장하므로 개인 사진 결과 화면에 재사용하지 않는다.
- 비공개 `fashion_app/build/p21-private/state.py`는 QA 전면 여부를 검사하고 UI XML을 기기에 둔 채 고정 문구의 존재 여부만 출력하도록 준비했다. 구문 검사만 완료, 아직 기기 실행하지 않았다. 사진·수치·체형 분류·전체 XML·스크린샷을 PC로 가져오지 않는다.
- 결과 사진의 실제 방향·어깨/허리/골반 측정선 위치는 사용자의 기기 화면 확인이 필요하다. 사진 요소와 안내 문구의 존재만으로 좌표 정합성을 통과 처리하지 않는다.
- P18 합성 방향/디코딩/좌표 통과 결과는 재사용하지만 실제 사진 URI·기기 화면·측정 정확도의 검증으로 확대하지 않는다.
- 원본 데이터 보존의 새 기기 해시 비교는 수행하지 않았다.

## 이어서 수행할 순서

1. 사용자가 QA 전면 전환과 실제 키 확인을 완료한 뒤 현재 화면을 최소 상태로 확인한다. 다른 앱이 전면이면 조작을 중단한다.
2. 필요한 경우 QA의 사진 선택 화면까지만 연다. 갤러리 탐색·선택은 사용자가 지정한 한 장을 직접 수행한다. 앱의 분석 동의도 사용자가 확인한다.
3. 로컬 분석의 Success/Partial/오류를 구분한다. 거절 사유를 확인하되 품질 기준 완화·임의 결과 주입·다른 사진 대체는 하지 않는다.
4. 유효 결과가 나오면 사용자에게 방향·측정선 위치를 확인받고, 결과의 스타일 제안으로 이동해 동일 분석 연결 여부를 개인정보 없이 확인한다. 저장은 QA 승인 범위에서만 수행한다.
5. 가능하면 QA 아바타 피팅 모드 진입·복귀만 확인한다. 기존 사용자 기록이나 테스트 옷을 변경하지 않는다.
6. 실제 결함이 있을 때만 최소 수정·관련 테스트. 코드가 그대로면 기존 18001 APK를 유지한다.

## 개인 사진 VTON의 기존 차단 조건

사용 권한과 접속 수단이 확인된 CUDA 실행 환경이 없다. 새 GPU 후보 조사·계정 생성·결제·다운로드는 하지 않았다. 환경이 제공되면 기존 `backend/LOCAL_VTON_SERVER.md` 순서대로 모델/Parser 라이선스와 checksum 확인 → 승인 후 가중치 준비 → 별도 서버 인증 → 단일 worker/HTTPS → 허가 입력의 실제 생성 → 개인 사진의 수신 환경·보관·삭제 조건에 대한 별도 동의가 필요하다.

이번 로컬 체형 분석 승인은 개인 사진 VTON이나 사진 외부 전송 승인이 아니다. 현재 전신 분석·스타일 연결·아바타 모드 검증은 완료로 보고하지 않는다.

문서 체크포인트는 기존 브랜치에 `[skip ci]`로 보관한다. 원격 일치 및 해당 SHA는 최종 응답에 기록한다. 비공개 도구·기기 식별값·사진·분석 결과는 Git에 넣지 않는다.
