# 발표 전 실기기 리허설 체크리스트

자동 테스트와 실제 기기 확인을 구분한다. 아래 체크박스는 실제 폰에서 확인한 사람이 체크한다. 이번 클라우드에서 실기기/에뮬레이터/실제 사진/유료 API는 실행하지 않았다.

## 발표 APK 및 데이터 보존

- [ ] GitHub Actions에서 최종 발표 커밋의 녹색 성공 실행을 선택한다. Artifacts의 body-analysis-stabilized-debug를 PC에서 다운로드·압축 해제한다.
- [ ] BUILD_INFO.txt의 커밋과 applicationId com.jeiu.fashionproject, versionCode3, versionName1.0-presentation을 확인한다. SIGNATURE.txt와 SHA256SUMS.txt도 보관한다.
- [ ] 기존 앱과 인증서가 같은지 확인한다. 같은 서명이면 `adb install -r body-analysis-stabilized-debug.apk`로 데이터 보존 업데이트 설치한다. 서명 불일치면 기존 앱을 삭제하거나 데이터를 초기화하지 말고 기존 서명키/백업 방법을 확인한다.
- [ ] 폰 모델/Android 버전/페이지 크기/권한/화면 배율을 기록한다. `adb shell getconf PAGE_SIZE`로 16KB 여부도 확인한다. 기존 MediaPipe arm64 라이브러리의 16KB 경고는 남아 있으며 16KB 실기기 실행을 보장하지 않는다.
- [ ] 기존 옷장·관심·착용·설정·체형 기록이 유지되는지 확인한다. 테스트를 위해 기존 사용자 DB를 비우지 않는다.

## 체형분석 (우선)

- [ ] 온보딩→홈→마이페이지→체형분석으로 진입한다. 키 입력(필수)과 cm 환산 이유가 보인다.
- [ ] 키가 비어 있어도 촬영/선택 버튼을 눌러 입력 안내로 갈 수 있다. 잘못된 키는 계속 진행할 수 없고 유효한100~230cm 입력 후 처음 선택한 작업으로 한 번만 이어진다.
- [ ] 키보드가 입력창을 가리지 않고 스크롤할 수 있다. 키보드 완료 또는 촬영/선택 탭 시 닫힌다. 작은 화면·글자 확대·가로 회전도 확인한다.
- [ ] 분석 이용 동의와 선택적 숫자 기록 저장을 구분한다. 저장 기본 OFF이고 취소하면 촬영/선택/분석을 시작하지 않는다.
- [ ] 동의 후 카메라 권한 허용/거부, 카메라 진입·자동/수동 촬영·복귀·재촬영을 확인한다. 거부 시 앱 종료가 아닌 설명/재시도가 가능하다.
- [ ] 시스템 사진 선택기에서 선택/취소/다시 선택을 확인한다. 취소 시 빈 화면이나 이전 사진 자동 분석이 없다.
- [ ] 정면 전신 사진에서 결과→사이즈 추천→체형 기반 스타일/코디 추천으로 이어진다. 너비를 둘레로 안내하지 않는다.
- [ ] 잘림·측면·어두움·가림·경계 조건에서 판정 보류/오류와 다시 촬영하기를 확인한다. 강제 유형이나 가짜 허리를 만들지 않는다.
- [ ] 같은 원본을 반복 분석하고 회전/반전 EXIF 사진도 비교한다. 실제 정확도/오차를 직접 기록하며 합성 테스트 결과를 정확도 수치로 대체하지 않는다.
- [ ] 빠른 연속 선택/화면 이탈/취소/재시도/긴 처리에서 오래된 요청이 덮지 않고 로딩이 끝난다. 타임아웃은 native 작업/서버 요금 취소를 보장하지 않는다.
- [ ] 저장 OFF는 새 서버 체형 기록을 만들지 않지만 현재 유효 세션으로 추천을 사용할 수 있다. 저장 ON 검증은 별도 개발 DB에서만 한다. 기존 기록을 임의 삭제하지 않는다.
- [ ] 새 분석이 실패했을 때 이전 유효 세션/저장 기록을 새 성공처럼 표시하지 않는다. 사진/이번 결과/과거 기록의 출처를 확인한다.

## 옷장·추천 전체 흐름

- [ ] 옷 등록→내 옷장 표시→내 옷 즐겨찾기 및 쇼핑 관심 설정→전체/내 옷/관심 옷 필터→각 범위 코디 추천을 확인한다.
- [ ] 기존 이미지·상품 이름·가격(제공되는 카드)·구매/상세 링크를 확인한다. 카테고리 및 기존 카드 구성을 유지한다.
- [ ] 배너3개가 초기 표시되고 아래 스크롤에서 실제 높이를 비운다. 목록 중간에서 방향을 바꿔도 갑자기 펼쳐지지 않고 최상단에서 돌아온다.
- [ ] 필터는 고정되고 상품과 겹치거나 터치를 막지 않는다. 하단 등록/피팅/추천 버튼·내비게이션도 확인한다.
- [ ] 빈 옷장/관심 없음/필터 결과 없음/긴 이름/홀수 카드/화면 회전/탭 재진입을 확인한다. 사용자 옷을 지워 빈 상태를 만들지 말고 격리된 테스트 설치를 쓴다.
- [ ] 날씨/TPO/취향/착용기록을 바꿔 추천 입력이 유지되는지 확인한다.

## 수동 배치와 AI 피팅

- [ ] 전신 사진→옷 선택→수동 이동/확대·회전·투명도/초기화를 확인한다. 자동 정렬이 AI 생성이 아니라는 설명이 보인다.
- [ ] 작은 화면에서도 별도 조절 패널을 스크롤해 크기·투명도·의류 목록을 모두 조작할 수 있다. 캔버스 드래그와 패널 스크롤이 충돌하지 않는다.
- [ ] AI 미설정 상태는 생성 성공/자연스러운 합성을 약속하지 않는다. 수동 배치는 계속 사용할 수 있고 옷 미선택은 선택 화면으로 돌아갈 수 있다.
- [ ] v1.6의 신발·액세서리 미지원 안내가 보인다. 원피스/중복 상의 충돌도 선택 정리를 안내한다.
- [ ] 실제 FASHN 검증은 키/크레딧/현재 요금 및 사전 유료 호출 승인 후에만 한다. 키를 화면·로그·발표 자료에 쓰지 않는다. 앱 내 키 대신 서버 proxy 전환은 별도 미완료 과제다.
- [ ] 생성 전 대상/목적/원본·중간 결과 전송/요청 수/비용 동의를 받는다. 거부하면 전송하지 않는다. 드래그 좌표는 AI에 반영되지 않는다.
- [ ] 인증401·크레딧402·네트워크 실패·시간 초과·재시도·중복 탭을 확인한다. 성공은 실제 API 결과일 때만 표시한다.
- [ ] 승인된 테스트에서 원본 비교/JPEG 저장/파일 선택 취소를 확인한다. 얼굴·의상 디자인·제품 핏 보장을 하지 않는다. 상의+하의는 순차2출력이며 추가 비용/품질 변화를 기록한다.

## 네트워크 실패·발표 대비

- [ ] 인터넷을 끈 상태에서도 기존 로컬 옷장·수동 배치·지원 모델이 준비된 로컬 체형분석·일반 추천을 확인한다. 모델 준비 여부도 기록한다.
- [ ] 네이버/날씨 오류는 해당 화면에서 안내하고 다른 기능은 계속 사용할 수 있다. 서버/사이즈표/히스토리 미연결도 전체 앱 종료로 이어지지 않는다.
- [ ] 준비된 API키·계정·네트워크 상태를 값이 아닌 설정 유무로만 기록한다. 외부 기능이 실패하면 발표에서 미설정/오류 안내와 로컬 대안을 설명한다.

## 자동 검증 범위

Android197개(기존191+P0 Compose3+P1 Compose3), 이 중 Robolectric Compose17개를 실제 JVM/API35에서 실행했다. Backend11개는 격리 DB 테스트다. 관련 Android instrumentation7개는 컴파일했으며 기기에서 실행하지 않았다. 실행 로그와 최종 수치는 PRESENTATION_QUALITY_REPORT.md 및 동일 SHA Actions 보고서를 따른다.
