## 빌드·설치

- Android Studio에서 `capston-second-main/fashion_app/`을 연다. JDK 21과 프로젝트 Gradle wrapper 9.3.1, SDK Platform 37/37.0 및 필요한 build tools를 준비한다.
- Linux: `bash gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug --console=plain --max-workers=2`
- Windows: `gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:lintDebug --console=plain`
- APK 산출 위치: `app/build/outputs/apk/debug/app-debug.apk`. 설치 예: `adb install -r app/build/outputs/apk/debug/app-debug.apk`.
- [ ] 기존 데이터가 있는 설치를 백업하고 업데이트 설치한다. 설치 오류가 서명 불일치라면 앱 데이터를 임의 삭제하지 않는다. 기존 서명/개발 담당자와 확인한다.
- [ ] 앱 실행 후 기존 옷장·관심상품·착용 기록이 유지된다.

## 필수·선택 설정

| 기능 | 필요한 설정 | 미설정/실패 시 확인할 동작 |
|---|---|---|
| 체형분석 | 카메라 권한(촬영 시), 사진 선택 권한/URI, ML Kit·번들 selfie_segmenter.tflite 실행 가능한 기기 | 명확한 실패/재촬영 안내. 외부 API 키는 체형분석에 필요하지 않음 |
| 기본 코디 | 등록한 보유 옷, 필요한 상의/하의 또는 원피스·신발 | 부족 아이템 안내, 앱 종료 없음 |
| 날씨 | local.properties의 선택 OWM_API_KEY, 인터넷·위치 권한 | 날씨 오류/기존 fallback 안내. 실제 응답은 기기에서 확인 |
| 네이버 스타일/쇼핑 인사이트 | local.properties의 NAVER_API_KEY_ID, NAVER_API_KEY 및 인터넷 | 오류 안내. 실제 API 연결은 이번 자동 검증 범위 밖 |
| 무신사 옷장 | 기존 성별 설정·데모 상품/이미지 | 화면 진입·성별 반영을 기기에서 확인 |
| FASHN | local.properties의 FASHN_API_KEY, 인터넷·크레딧 | 미설정 시 서비스 준비 안내. 전송은 별도 확인 후에만 |
| DB·히스토리·사이즈표 | 개발 Backend 주소 및 필요한 DB/사이즈표 | 서버 없으면 오류 안내·일반 추천/기기 내 분석 유지 |

`local.properties`/`.env`와 실제 키 값은 Git에 올리거나 발표 자료·로그에 표시하지 않는다. 기존 FASHN/NAVER 등의 클라이언트 BuildConfig 키는 APK에서 추출될 수 있으므로 운영 전 인증된 서버 proxy/키 교체 정책이 필요하다. 과거 노출된 키는 교체한다. 이번 작업은 외부 proxy 배포를 완료한 것이 아니다.

- Backend 기본 앱 주소는 `BackendApi.BASE_URL = http://10.0.2.2:8000` (Android 에뮬레이터의 개발 PC).
- 실제 폰은 개발 PC와 같은 네트워크에서 개발 PC LAN 주소의 8000 포트를 사용한다. 실제 통신/방화벽/TLS 설정은 환경에 맞게 검증한다.
- Backend 실행: `backend`에서 가상환경 활성화 후 `python -m uvicorn main:app --host 0.0.0.0 --port 8000`.
- 운영 DB를 시험 대상으로 사용하지 않는다. 기존 DB를 초기화하지 않는다. 설정된 DB의 `DB_AUTO_CREATE`와 스키마를 먼저 확인하고 기존 DB에서는 자동 생성/마이그레이션을 임의 실행하지 않는다.
- 격리된 시연 사이즈표 서버: `backend`에서 `python demo_size_chart_server.py --host 0.0.0.0 --port 8000`. 실제 인체 기록을 시드하지 않는 개발 전용 SQLite 서버다. 운영 서버와 같은 포트에 동시에 실행하지 않는다.
- 외부 기능의 코드상 목적지: OpenWeatherMap, `naverapihub.apigw.ntruss.com`, `api.fashn.ai`, 상품/이미지 제공처. 실제 접근 권한·크레딧·키 유효성·네트워크는 확인하지 않았다. 임의로 네트워크 정책을 넓히지 않는다.

## 체형분석 시연 순서

- [ ] 키가 비어 있거나 유효하지 않아도 촬영·선택 버튼을 누를 수 있고, 먼저 키 입력 안내가 나온다. 유효한 키 입력·이용 동의 후 원래 선택한 작업이 한 번만 실행된다.
- [ ] 저장 동의를 철회한 초기 상태에서 큰 사진 선택 영역을 누르면 먼저 이용 안내가 나온다.
- [ ] 별도 사진 선택 버튼도 동일 안내가 나온다. 기록 저장 체크는 기본 OFF다.
- [ ] 안내를 취소하면 사진 선택/추론/서버 저장이 시작되지 않는다.
- [ ] 저장 OFF로 동의하고 정면 전신을 촬영한다. 팔을 몸에서 조금 떼고 무릎을 펴며 머리·발끝에 여유를 둔다.
- [ ] 가이드의 팔 분리/중앙/거리/정면 안내와 1.5초 자동 촬영, 수동 촬영 및 뒤로 가기를 확인한다.
- [ ] 갤러리의 정상 전신 사진도 같은 핵심 자세 검사를 따른다.
- [ ] 성공 시 사진 추정 체형·너비·cm가 표시된다. 너비는 둘레가 아니며 관절 참고값은 판정 정확도가 아니다.
- [ ] 다리 비율이 표시되면 `고관절~발목 cm / 입력 키 cm`와 일치한다. 머리 꼭대기~발바닥 높이로 환산하며 nose~ankle 대체값을 만들지 않는다.
- [ ] 저장 OFF여도 유효한 세션 측정값으로 사이즈/코디 추천이 가능하다. 사이즈표가 없으면 기존 오류 안내가 나온다.
- [ ] 정면 너비와 의류 어깨 단면만 비교하며 허리·힙을 둘레로 사용하지 않는다.
- [ ] 저장 ON인 별도 개발 DB에서만 숫자 기록 전송과 중복 방지·조회·삭제를 확인한다. 원본 사진은 체형 기록 API로 전송되지 않는다.
- [ ] 서버가 끊겨도 분석 성공과 저장 실패를 혼동하지 않는다. 연결 복구·대기열은 개발 DB에서 확인한다.

- [ ] 경계/실루엣 불확실 시 일부 측정 또는 분석 불가를 구분하며 네 체형 중 하나를 강제하지 않는다.

- [ ] 분석 취소/화면 이탈 후 늦게 도착한 결과가 다시 나타나지 않는다.

- [ ] EXIF 1~8(회전·반전), 가로/세로 이미지, 카메라·갤러리 경로를 각각 확인한다. 전면/후면 전환 버튼은 이번 병합본의 미구현 기능이며 이번 작업에서 추가하지 않았다.
- [ ] 헐렁한 옷/두꺼운 소매/가림/자세 변화는 별도 실패·오차 사례로 기록한다. 합성 테스트를 사람 정확도 수치로 환산하지 않는다.

- [ ] 무신사 옷장 피팅에서 사진이 미리 선택되어 있어도 자동 전송되지 않는다.
- [ ] 피팅 시작/재시도 시 FASHN 대상·목적·중간 결과 재전송·크레딧 안내가 나온다.
- [ ] 거부/닫기는 외부 전송을 시작하지 않으며 체형분석·기본 추천을 유지한다.

- [ ] 성별 설정, 네이버 스타일 검색, 추천 상품·관심 하트, 무신사 옷장, 쇼핑 화면 진입을 확인한다.
