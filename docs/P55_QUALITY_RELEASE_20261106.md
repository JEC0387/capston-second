## 실제 이미지 검수

P51 승인 인물·상품 원본 4장과 P54 상의+하의 중간 PNG, 신발 적용 최종 PNG를 직접 열어 비교했다. 이미지 수정·재생성·크레딧 조회·사진 업로드는 하지 않았다. 인물은 CC BY 4.0 합성 성인 이미지, 상품은 Met Public Domain 자료다. P54 귀속 문서와 원본을 그대로 보존했다.

확인된 원인 범위: 결함이 공급자 중간 출력에 이미 존재하며, 최종 전달 PNG와 기기 저장본은 같은 해시다. 따라서 Android 표시/저장 과정에서 주머니를 바꾼 결함은 아니다. 공급자 내부 모델·시드·강도는 공개되지 않아 내부 원인을 확정할 수 없다. 기존 요청은 색상·무늬·재단의 일반 보존만 기술했고 단추/주머니/굽의 구체적 제약이 없었다. 단일 상품 시점·가림·작은 최종 상품 영역도 가능한 요인이나, 추가 시험 없이 원인으로 단정하지 않는다.

상·하의 중간→최종 비교의 프레임별 RGB 평균 절대차는 상단 약 1.43–1.95, 허리/다리 약 2.28–2.90, 발/바닥 약 4.91–5.61 (0–255 스케일)이다. 좌표 사각형의 기술적 픽셀 차이일 뿐, 인체 분할·정체성·상품 일치 정확도나 품질 점수가 아니다. P55 비공개 `P55_EXISTING_ASSET_AUDIT.json`에 좌표와 해시를 기록했다.

P50 영역 합성은 이미 정렬된 영상·검수된 마스크가 필요하다. 원래 다른 옷을 입은 인물 픽셀을 복원하면 새 상품을 지우거나 경계를 망가뜨릴 수 있고, 새 재킷 단추를 생성하지 못한다. 원본 1024×1353과 결과 896×1184의 크기도 다르며 동일 크기로 맞추는 것만으로 정렬을 보증할 수 없다. 자동 적용·임의 마스크·얼굴 복사·상품 패턴 덮어쓰기를 하지 않았다.

## 실제 코드 변경

- `backend/genlook_request_contract.py`: 기본 `p54`와 별도 `reference-details-v1` 요청 정책. 새 정책은 공식 `products[].description` 안에서 관찰 가능한 상품 세부의 보존을 요청한다. 없는 단추 수·성별·옷 종류를 만들어 넣지 않는다.
- `backend/genlook_outfit_provider.py`: 운영자 명시 옵션을 실제 multipart 요청까지 연결. 정확한 정책 문구를 계약 해시에 포함해 과금 장부·Android 작업과 연결한다. 기본 요청/계약 해시는 그대로다. 별도 정책으로 기존 장부를 열면 차단하며 장부를 초기화하지 않는다.
- `backend/tests/test_genlook_p55_details.py`: 기본 호환성, 실제 어댑터 모의 전송, 역할별 문구, 3크레딧 제한, 장부 전환 차단, 기존 API 영수증 검증, 승인 없는 차단을 검사한다.
- `backend/GENLOOK_OUTFIT_PROVIDER.md`: 활성화 조건·품질 미검증·장부 재사용 금지 설명.

새 정책은 서버 생성자에서만 명시 선택할 수 있고 기본 배포 설정에 활성화하지 않았다. 기존 P54 실행 스크립트·환경파일·Android·인증·저장·중간 검수 게이트·과금 상한은 변경하지 않았다. 별도 운영 승인이 없는 상태에서 준비 완료를 반환하도록 우회하지 않았다. 결과의 `NOT_EVALUATED`를 PASS로 바꾸지 않았다.
